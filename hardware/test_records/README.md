## 二、跑了什么（可原地复跑）

```powershell
# ① 参数全量回读（0x24 只读，不写 Flash）
python tools\fw_prep\tune.py -p COM3 --dump

# ② 只读探测 12 s + 0x24 全量回读对照（★ 不发任何运动指令）
host\build-release\host.exe --probe COM3 --probe-seconds 12 --probe-readback -platform offscreen

# ③ 蓝牙 SPP 端口探测（各 8 s，只读）
host\build-release\host.exe --probe COM4 --probe-seconds 8 -platform offscreen
host\build-release\host.exe --probe COM5 --probe-seconds 8 -platform offscreen

# ④ ★ 观测**正在平衡的车**：必须加 --enable（见 §四 坑 1）
python tools\fw_prep\tune.py -p COM3 --observe 20 --enable --csv hardware\test_records\05_observe_balance_20s.csv

# ⑤ 带心跳的只读探测（保活但**不解锁**；用于看已锁存状态）
host\build-release\host.exe --probe COM3 --probe-seconds 10 --probe-readback --probe-heartbeat -platform offscreen
```

> `host.exe` 是动态链接 Qt 的：跑之前把 `D:\0_APP\QT\6.11.2\mingw_64\bin` 加进 `PATH`。

## 四、本次踩到/修掉的坑（都直接影响"数据能不能用"）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | **`tune.py --observe` 会把正在平衡的车"探停"**：观测窗口里后半段全是"电机已停"的数据，而工具照常给出统计量 | 固件规定 **500 ms 无下行帧 ⇒ 安全锁存**；`--observe` 只在进/出观测模式时各发一帧，中间 20 s 一声不响 ⇒ 0.5 s 后就被锁存 | ✅ 给 `tune.py` 加 **`--keepalive`**（每 200 ms 发 `0x1F` 心跳，保活**不解锁**）与 **`--enable`**（每 100 ms 发 `0x20 使能=1` 零速度，保活**并解锁**）；不加则打印警告。**观测运行中的车必须加 `--enable`** |
| 2 | **"零穿越"统计永远是 0**（车明显在摆，工具报"0 次 / 0.0 Hz"），没法用它判断振荡 | 用"一阶差分乘积 < 0"数局部极值；而 `0x10` 姿态与 `0x11` 运动都是 20 Hz、相邻两行常取到**同一个** pitch ⇒ 极值点两侧必有一个差分为 0 ⇒ 乘积 = 0 ⇒ 一次都数不到（根子上还有一处 off-by-one 已在修这个统计时一并改掉）| ✅ 换成经典定义：**信号穿过均值线的次数**，摆动频率 ≈ 过线次数 / 2 / 时长（`05` 的 35 次 ⇒ **0.86 Hz**，与观察到的摆动相符）|
| 3 | `host --probe-readback` 的 `0x16` 判读在**保护态**下会给出无意义的比例（`Moto −8200 → CCR 471`，比值 0.057；`Moto −2055 → CCR 838`，比值 0.408），却仍判"✔ 已执行" | 保护中（`Flag_Stop`/锁存）时 `Moto` 是"算出来的"、`CCR` 是"被执行/被截断的"，两者本来就不成 1.17 比例 | ⏳ **待 B 侧确认判据**：建议"保护位置位时不按 1.17 判"。**真机反证**：带使能观测（`07`）里 20 个未保护样点的比例稳定在 **1.167–1.170** ⇒ "1.17"本身是对的，只是**只在未保护时可作判据** |
| 4 | `0x16` 的 `Bal` 与 `0x10` 的俯仰量级不一致（如 `Bal −2055` vs 俯仰 −6.41°）| 待查（`Bal` 的零点/标度） | ⏳ 记入待确认（不影响本次结论）|

## 五、由原始值反推的一处交叉验证（MQ-135 到底有没有在工作）

分压网络 `AO —[10 kΩ]—┬— PA5 —[15 kΩ]— GND`，分压比 **0.600**（[`电路设计说明文档.md`](../../docs/design_hardware/电路设计说明文档.md) §6.1）：

```
V(PA5) = 122 / 4095 × 3.3 V ≈ 0.098 V
V(AO)  = 0.098 / 0.600      ≈ 0.16 V     ← MQ-135 模块 AO 实测（换算值）
```

对照"MQ-135 洁净空气 AO 常见 0.1–0.3 V"（外部资料，见 [`上板测试记录.md`](../../docs/design_hardware/上板测试记录.md) §6.1 的参考表），
**0.16 V 正落在该区间** ⇒ **模块在测、分压通路正常、ADC 通道没接错**。
（ADC 12 位 / 3.3 V 参考；0.098 V 只有约 122 个码，量化误差约 ±0.008 V ⇒ 只看量级，不看小数后两位。）

| 项 | 为什么没做 | 需要什么 |
|---|---|---|
| **完整任务链记录**（上电→预热→待机→下发任务→巡检含一次气体报警→返航→完成）| 需要车能自主行驶 + 场地 + 演示气源；本次只做了"静止平衡观测" | 人扶正/清场 + 演示气源（酒精棉球）|

| **PID 整定前后对比** | 只取到"当前基线"（`01`），没有"调整后" | 一次现场整定（前后各 `--dump` 一次）|
| 蓝牙端到端 | COM4/COM5 打开后 0 B | 确认模块处于 SPP 从机并已"连接"、或继续用有线 |

> ⚠️ **每次测试结束后的状态**：我们一停手，链路就静默 ⇒ **500 ms 后板子按设计锁存安全停车**（车会停、可能倾倒）。
> 要继续跑：在**上位机界面点"使能"或"下发任务"**解除锁存（或重新上电）。
