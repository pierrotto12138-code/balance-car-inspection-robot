# 固件架构设计（角色 B）

> 基线：`Base/高配版平衡小车附送资料（STM32F405RGT6）/MiniBalanceV5.0【高配版】平衡小车库函数版源码（卡尔曼滤波版）`
> 架构决策：**混合式** —— 平衡控制保留在中断中，其余功能进 FreeRTOS 任务
> 更新日期：2026-09-22

---

## 一、为什么选混合式架构

### 1.1 基线的现状（读源码得出）

| 项目 | 现状 |
|---|---|
| 调度 | **裸机超级循环**，无 RTOS |
| 控制节拍 | 由 **MPU6050 的 INT 引脚触发外部中断**（`EXTI15_10_IRQHandler`），用 `Flag_Target` 交替出两个节拍 |
| 节拍分工 | **5 ms**：读姿态 + 读遥控 + 读电池；**10 ms**：读编码器 + 三环 PID + PWM 输出 |
| 姿态 | `Get_Angle(Way_Angle)`，`Way_Angle=2` 时为卡尔曼 |
| 主循环 | `while(1)`：刷新 APP/OLED 或跑 DataScope，靠 `delay_flag` 等中断给节拍 |

### 1.2 两个方案的取舍

| 方案 | 优点 | 风险 |
|---|---|---|
| **全面 FreeRTOS 化**（控制也进任务） | 架构统一，报告好写 | 控制节拍从**硬件中断**变成 **RTOS 节拍**，抖动变大；现有已调好的 PID 参数可能要重调；调试周期明显变长 |
| **混合式（选定）** | 平衡控制的时序**完全不变**，现有参数可直接沿用；新功能天然并发 | 中断与任务共享数据需加保护 |

**决策理由**：平衡车对控制时序极其敏感，而项目只有三周。**不拿已调好的平衡去冒险**，
把 FreeRTOS 用在它真正有价值的地方（气体采集、通信、状态机、界面这些可以并发等待的功能）。

## 二、任务划分

### 2.1 保留不动（中断上下文）

| 功能 | 周期 | 说明 |
|---|---|---|
| **控制中断** | 5 ms / 10 ms 交替 | `EXTI15_10_IRQHandler`：姿态读取、三环 PID、PWM 输出、异常保护 |

> **本部分原则上不改**，只在其中**新增**一件事：把姿态/速度等数据快照到共享结构体，
> 供任务读取（见第三节）。

### 2.2 新增 FreeRTOS 任务

| 任务 | 优先级 | 周期 | 职责 | 依赖 |
|---|---|---|---|---|
| **GasTask** | 中 | 1000 ms 常态 / 200 ms 异常 | 读双路 MQ 的 ADC、读 DHT11、温湿度补偿、超阈值研判、更新采样档位 | ADC、DHT11 |
| **CommTask** | 中 | 20 ms（上行）/ 200 ms（心跳） | 按协议组包上行状态、解包下行指令、入队分发 | USART2（蓝牙） |
| **TaskTask**（状态机） | 中 | 100 ms | 巡检阶段迁移、巡检点管理、避障决策 | 编码器、超声波 |
| **UiTask** | 低 | 100 ms | OLED 刷新、按键扫描、蜂鸣器报警 | OLED、KEY、蜂鸣器 |

> **注**：`TaskTask` 与基线已有的 `Bi_zhang`（避障/跟随模式）逻辑有重叠，改造时应融合而不是并列。

### 2.3 任务间通信

| 通道 | 类型 | 用途 |
|---|---|---|
| `xQueueGas` | 队列 | GasTask → CommTask（气体数据） |
| `xQueueCmd` | 队列 | CommTask → TaskTask（下行指令） |
| `xQueueEvent` | 队列 | 各任务 → CommTask（事件告警上行） |
| `g_state` | **共享结构体 + 临界区** | 控制中断 → 各任务（姿态、速度快照） |
| `xMutexI2C` | 互斥量 | 保护 MPU6050 与 OLED 的 I2C 访问 |

## 三、中断与任务的数据共享（关键）

这是混合架构**唯一的风险点**，必须处理好。

### 3.1 问题

控制中断每 5 ms 更新 `Angle_Balance`、`Gyro_Balance`、`Gyro_Turn` 等 **32 位 float**。
任务若在中断写这些变量时读取，可能读到**半更新**的值（高位旧、低位新）。

### 3.2 做法

```c
/* 控制中断内：更新快照（放在中断末尾） */
void snapshot_state(void)
{
    taskENTER_CRITICAL_FROM_ISR();
    g_state.angle   = Angle_Balance;
    g_state.gyro    = Gyro_Balance;
    g_state.gyroTurn= Gyro_Turn;
    g_state.encL    = Encoder_Left;
    g_state.encR    = Encoder_Right;
    g_state.volt    = Voltage;
    g_state.seq++;              /* 序号，供任务判断是否更新 */
    taskEXIT_CRITICAL_FROM_ISR();
}

/* 任务内：整块读取 */
StateSnapshot get_state(void)
{
    StateSnapshot s;
    taskENTER_CRITICAL();
    s = g_state;
    taskEXIT_CRITICAL();
    return s;
}
```

**要点**：
- 快照用**整块结构体**拷贝，不要逐个字段读（逐个读仍可能跨两个节拍）；
- 临界区**必须极短**（只做赋值），否则会拉长中断、破坏控制时序；
- 若某数据更新频率低（如电压），可加**序号**让任务判断是否为新值。

### 3.3 互斥量保护 I2C

基线本身已有此问题的教训（旧基底就因 OLED 与 IMU 共用 I2C 而加了互斥锁）：

- MPU6050 与 OLED **共用软件 I2C**；
- `UiTask` 刷 OLED 时若中断里正在读 MPU6050，会**总线冲突**；
- 解法：所有 I2C 访问前 `xSemaphoreTake(xMutexI2C, ...)`。

> ⚠️ **待确认**：若 MPU6050 是独立模块、走的是**硬件 I2C 引脚**而非 PB10/PB11，
> 则要与 OLED 的总线关系重新核实（见 `car_composition.md` 第 6.2 节）。

## 五、新增代码目录建议

```
firmware/
├── Core/                      # CubeMX/Keil 生成（时钟、中断、外设初始化）
├── Drivers/                   # FWLIB 标准外设库
├── Middlewares/FreeRTOS/      # FreeRTOS 源码
├── App/
│   ├── Control/               # PID 三环（沿用基线）
│   ├── Sensor/
│   │   ├── mpu6050.c          # 沿用基线
│   │   ├── gas.c              # ★ 新增：双路气体 + 补偿
│   │   └── dht11.c            # ★ 新增：温湿度
│   ├── Task/
│   │   └── patrol.c           # ★ 新增：巡检状态机
│   ├── Comms/
│   │   ├── protocol.c         # ★ 新增：自研协议组包/解包
│   │   └── crc16.c            # ★ 新增：CRC-16/MODBUS（与上位机同算法）
│   └── Ui/                    # OLED + 按键 + 蜂鸣器
└── User/                      # 任务创建与调度
```

> **CRC-16 必须是同一份实现**：上位机侧已实现并通过测试（`host/src/protocol/crc16.cpp`），
> 固件侧照它翻译成 C，并用协议文档第 2.1 节的用例交叉验证。

## 六、安全机制（沿用基线已有的）

基线已实现，**必须保留**：

| 机制 | 位置 | 阈值 |
|---|---|---|
| 倾角保护 | `Turn_Off()` | 超过 ±40°（相对机械中值）关电机 |
| 低电压保护 | `Turn_Off()` | 低于 11.1V 关电机 |
| PWM 限幅 | `Xianfu_Pwm()` | ±8200（满幅 8400） |
| 积分限幅 | `velocity()` | ±10000 |
| 拿起检测 | `Pick_Up()` | 三步状态机 |
| 放下检测 | `Put_Down()` | 两步状态机 |

**需新增**：

- **通信失联保护**：500 ms 未收到下行帧 → 安全停车（协议第 5 节）；
- **预热期保护**：气体传感器预热未完成时，不上报浓度真值，只报状态位 → 避免误导。
