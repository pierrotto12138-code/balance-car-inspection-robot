# 编码规范（B 阶段固件）

> **为什么要有这份文件**：这个工程的"优雅"不是排版好看，而是三条硬约束 ——
> **① 同一件事只有一个真相；② 依赖单向；③ 能被 PC 单测**。
> 下面的规则都是从**实际踩过的坑**里总结的（每条都指向一个具体事故或复查发现），
> 新人照它写，就不会重复踩。
>
> 适用范围：`firmware/App/`、`firmware/User/`、`firmware/System/`、`firmware/tests/`
> （厂商 `Drivers/FWLIB`、`Middlewares/FreeRTOS` 保持原样，只做必要的移植改动并标 `★`）。
> 校验手段：`make strict`（严格告警，0 条）、`python tools/fw_prep/run_all_tests.py`（断言全过）。

---

## 一、分层与依赖方向（谁能 include 谁）

```
User/            启动、中断入口、内核配置           → 可以 include 任何层
App/Task/        任务编排与状态机                   → App/Comms, App/Sensor, App/Control, App/Ui, System, Drivers/BSP
App/Comms/       协议、环形缓冲、串口胶水            → App/Config, System（不得反向依赖 App/Task）
App/Sensor/      气体/DHT11/ADC/组包                → App/Config, Drivers/BSP
App/Control/     PID 与参数持久化                   → App/Config, Drivers/BSP
App/Ui/          显示页、蜂鸣器                     → App/Config, App/Task/app_api.h（只读接口）, Drivers/BSP
App/Config/      纯宏定义                           → 不 include 任何东西
System/          厂商移植层（sys/delay/usart）       → 不得 include App/**（见第四节"反例"）
Drivers/BSP/     外设驱动                           → 不得 include App/**
```

**规则 1（单向）**：箭头只能往下，**不许回指**。底层需要"上层才知道的事"时，用**回调/钩子注入**
（例如演示：`delay.c` 需要知道调度器是否在跑 → 由 App 在启动时注册函数指针，而不是 `extern App_...`）。

**规则 2（厂商全局量只在一处声明）**：厂商全局量（`Angle_Balance`、`Moto1/2`、`Voltage`、
`Flag_Stop`、PID 增益、`Zhongzhi`…）**统一由 `System/sys/sys.h` 声明**，业务代码
`#include "sys.h"` 即可，**不要在各文件里再写 `extern`**。
> 事故：`app_tasks.c`/`param_store.c` 各自 `extern` 了一遍，`make strict` 报
> `-Wredundant-decls` 11 条；更糟的是改一处漏一处。

## 二、"只有一个真相"（本项目最容易犯的错）

| 规则 | 说明与事故 |
|---|---|
| **同一计算只留一份实现** | 0x14 载荷（就绪位 + ppm×10）只由 `SensorReport_FillEnvGas()` 算；`App_GetGas()` **复用它**，不许另写一套。<br>事故：曾有两套等价实现，测试只覆盖了"没人调用"的那份 → **给死代码写了测试**。 |
| **校验必须真的比对** | 任何"写入后回读校验"都要**逐字段比较**，不能只判断"读得回来"。<br>事故：`ParamStore_Save()` 只 `Unpack` 一次、从不与源数据比对 —— 与铁律 29 同型的**假校验**。 |
| **使能/停车只有一个权威** | `App_MotorDisable`（任务侧锁存）是唯一权威，厂商 `Flag_Stop` 只是**执行器**（中断据前者强制置位）。<br>事故：`Put_Down()` 的"放下自动使能"曾能绕过安全锁存。 |
| **接口承诺必须兑现** | `app_api.h` 说"getter 自带短临界区"，那每个 getter 就都得有。<br>事故：4 个 getter 里只有 1 个加了临界区，属于**文档骗人**。 |
| **死代码零容忍** | 没人调用的函数要么删、要么在头文件注明"这是外部工具入口（固件内不调用）"，例如 `App_GetTelemetry()`/`App_TaskTicks()`。 |

## 三、可测试性（这是本项目最有价值的习惯）

1. **算法与硬件分离**：协议、气体换算、状态机、里程计、参数打包一律写成**只依赖 `<stdint.h>`** 的纯 C；
   时间由调用方注入（`Proto_Feed(..., nowMs, ...)`）、标定系数由外部注入（`Odom_SetScaleUmPerCount()`）。
2. **凡是"决策逻辑"都要有断言**：新增分支必须在 `firmware/tests/*.c` 里补断言，
   并且**同时覆盖边界与最坏值**（例如 ppm 饱和钳位 1e6 → 65535）。
3. **不用自己写的解析器验证自己的改动**（AGENTS 铁律 23）：协议正确性靠
   Python 独立实现 ↔ host C++ ↔ 固件 三方交叉验证（`docs/protocol/test_vectors.json`）。
4. **改完必须跑**：`python tools/fw_prep/run_all_tests.py` + `make strict`，两条都绿才算完。

## 四、中断与并发（混合式架构的命门）

1. **高于 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`(5) 的中断里，绝不调用任何 FreeRTOS API**
   （含 `...FromISR`）。本项目 `EXTI15_10`(1)、`USART1/2`(0) 都属于这一类。
   校验：`python tools/fw_prep/check_isr_safety.py`。
2. **中断里只做"塞缓冲 / 读一个变量 / 纯整数加"**：解帧、格式化、字符串、浮点、除法一律留给任务。
3. **中断与任务不共用外设**（本项目把气体挪到 ADC2；临界区**挡不住**高优先级中断）。
4. **getter 要么加短临界区、要么只读单写者的原子量**；共享结构体跨任务读必须按前者。
5. **临界区里不调用函数**（除纯计算）：`App_GetDiag()` 把 `xPortGetFreeHeapSize()` 放在临界区外。

## 五、命名与文件组织

| 对象 | 规范 | 例 |
|---|---|---|
| 模块前缀 | 与模块名一致，动词在前 | `Gas_Update`、`Patrol_Tick`、`Proto_Encode`、`Odom_AddCounts` |
| 文件内静态量 | `s_` 前缀 | `s_patrol`、`s_mq2RawAvg` |
| 常量/配置 | `CFG_` 前缀，集中在 `App/Config/app_config.h` | `CFG_WARMUP_MS`、`CFG_TX_ENV_FAST_MS` |
| 协议字面量 | `PROTO_` 前缀 | `PROTO_DOWN_PID_TUNE` |
| 公开接口 | 头文件成对，放对应模块目录 | `App/Task/app_api.h` |
| 类型 | `XxxCfg`（配置）/ `XxxState`（状态） | `PatrolCfg`、`GasChannelCfg` |

- **头文件守卫用 `APP_XXX_H` 风格**（不要 `__XXX_H`：`__` 开头是 C 保留标识符，属未定义行为）。
- **文件头写"这个文件负责什么、为什么这么设计"**，不要写"本文件实现了 X"这种废话。
- **注释写"为什么"，不写"是什么"**：`/* 用 ADC2 是因为中断占用 ADC1，临界区挡不住中断 */` ✅。

## 六、注释与文档同步

1. 改了行为 → 同步改注释与文档（`程序说明文档.md`/`README.md`），**注释与实现不一致按 bug 处理**。
2. 数值型参数（阈值、预热、周期）**必须在注释里写清"为什么是这个数"**（见 `app_config.h` §四/§五）。
3. 厂商文件被我们改过的地方，一律用 **`★ B yyyy-mm-dd（决策 N）`** 标注，便于区分原文与改动。

## 七、提交前自检（照抄执行）

```powershell
cd <仓库根>/firmware
make                 # 正常构建（应无 error；厂商代码的历史告警允许存在）
make strict          # 严格告警：**自研代码必须 0 条**
cd ..
python tools\fw_prep\run_all_tests.py    # 4 套断言 + 交叉编译 + 向量表 + 中断安全 + 引脚基线
python tools\fw_prep\check_isr_safety.py # 动过中断/内核配置时
```

> 严格告警为什么重要：`-Wall -Wextra` 挡不住**类型窄化、隐式符号转换、缺原型**这类问题，
> 而它们往往在换编译器、换优化等级、或上板后才暴露。我们把它固化成 `make strict`（厂商头用 `-isystem` 屏蔽）。
