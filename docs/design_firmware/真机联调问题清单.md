# 真机联调问题清单（2026-10-13 首轮上板）

> 本文是**全量正确性检查**的结论汇总，不是规范检查。方法见 §1，清单见 §3，明天上板的动作顺序见 §4。
> 每条都带 `文件:行` 与证据；**已修**的条目同时记进了 [`docs/决策记录.md`](../决策记录.md) 决策 60/61。

## 1. 检查方法与一个必须先纠正的前提

**三路独立审计 + 一次自查**（各自只读、要求逐条给证据，不采信彼此结论）：

| 路 | 范围 | 方法 |
|---|---|---|
| ① 厂商文件差异 | 我们手改过的每个厂商文件 | 注释感知去注释 + GBK/UTF-8 解码 + 折空白 → 逐行序列比对，每个非平凡 hunk 人工读码 |
| ② 自研代码正确性 | `App/**`、`User/`、测试 | 并发/RTOS/时间回绕/安全通路/传感器算法/协议/持久化逐项过 |
| ③ 按上板症状反推 | 现象 → 代码 → 可测的量 | 每个症状给候选原因表 + "最少步骤证实/排除" |

**★ 纠正一个前提**：我们的厂商基线是**「库函数版源码（卡尔曼滤波版）」**，不是 DMP 版。
因此 `Way_Angle=2`、`Zhongzhi=1`、`stmflash.c` 的 `0X08020000`、`show.c` 的 `"F4"` **都是厂商原样**，
不是我们改的（此前"`Way_Angle` 从 1 改成 2"的说法**不成立**，特此更正）。

**★ 另一个必须记住的教训**：`make strict` 在**增量编译**下可能什么都不编 → 报"0 条"是假绿。
必须 `make clean` 后再跑。本次就是 clean 之后才暴露出 `show.c` 的几十条 `-Wpointer-sign`。

## 2. 一句话结论

**安全停车锁存链本身是好的**（`safetyStop` → `Patrol_MotorsDisabled` → `App_MotorDisable` →
中断强制 `Flag_Stop=1` → `Turn_Off()` → 跳过 `Set_pwm()` + 清方向脚），
厂商的"放下自动使能"与"按键启停"两个旁路也都已堵上（铁律 29 那一类问题**已修好**）。
当前的危险不在锁存链，而在**三个外围环节 + 一个功能断链**（见 §3 的 A 组）。

## 3. 发现清单

### A 组：会炸 / 功能不可达（必须处理）

| # | 位置 | 问题 | 后果 | 状态 |
|---|---|---|---|---|
| A1 | `Drivers/BSP/USARTX/usartx.c:88-170`、`App/Task/patrol.c:149-160`、`board_state.c` | **运动指令断链**：RTOS 下**没有任何人能置位** `Flag_Qian/Hou/Left/Right`（厂商写者在 `#else` 里被编掉；另两个写者分别依赖未装的航模接收机与 CAN 帧）；0x20 的线/角速度 `data[0..3]` 在 `patrol.c` 被**直接丢弃**（只读 `data[4]` 使能位） | **车只会原地平衡、不会前进/转向** → 任务书"自主行进 / 覆盖率≥90%"不可达 | **待修**（最高优先） |
| A2 | 审计 #3 + 症状反推 | **低压误触发**：`in.hwFault = (电压>0 且 <11.10V)` | 一上电即误锁存 FAULT → `Turn_Off()` 恒 1 → `Set_pwm()` 永不执行 → **电机毫无输出、车不能平衡** | **已修**（三级判据：>6.00 V 才算有电池 + 连续 5 拍确认） |
| A3 | `App/Sensor/dht11_hw.c` | **DHT11 位操作全程不屏蔽中断**，而控制中断每 5 ms 抢占 26~70 µs 的位窗口 | 校验失败 → 上百毫秒重试空转 → `T/H` 长期 N/A（**与实测现象一致**），且拖住 GasTask | **已修**（响应+40 位整段进临界段，所有出口都恢复中断；20/30 ms 等待留在开中断状态以免在关中断时调 `vTaskDelay`） |
| A4 | `App/Control/control.c:45` | **厂商 Flash 读路径保留、写路径被删**：`Flash_Read()` 读 `0x08020000`，而 RTOS 下无人写它（我们的持久化在 `0x08040000`）→ 空白判据恒真 → 把 4 个 PID 增益**静默写回 300/1/80/0.4**；且厂商把 10×u32(40 B) 读进 `u16[10]`(20 B) 本身越界 | **调好的参数被静默覆盖**（"存了却变回默认"） | **已修**（RTOS 构建下整段隔离，参数唯一权威 = `ParamStore`） |
| A5 | `App/Control/control.c:250-264` | `Turn_Off()` 每 5/10 ms 拿 `Voltage` 判 11.10 V，而 `Voltage` 是 **0.5 s 才更新一次**的均值，且无迟滞/无连续确认（与自研三级判据不是同一套） | 电池临界时**整段时间无输出** → 平衡车"突然软脚"→ 摔车 | **待修**（建议：复用 `s_lowBatCount` 的确认+迟滞，`1110` 改引用 `CFG_BAT_LOW_LIMIT`） |
| A6 | `App/Control/param_store.c:61` → `stmflash.c` → `stm32f4xx_flash.c` | **整扇区擦除**（0.4~4 s）在任务里同步执行，代码本身在 Flash 中跑（`.text > FLASH`），`FLASH_WaitForLastOperation()` **无超时** | 写参数期间控制中断被饿死 → 电机保持最后 PWM **数秒** | **待修**（保存前强制"安全停车 + 电机断电"；擦写函数搬到 RAM 并加超时） |

### B 组：会错（会静默给出错误结论）

| # | 位置 | 问题 | 后果 | 状态 |
|---|---|---|---|---|
| B1 | `App/Sensor/gas.c:196-216` + `sensor_report.c:39` | **R0 标定无有效性判据**：`Gas_VaoToRs` 在 `vao<=0` 时返回 0，`r0Sum += 0` 照样累加；`ready` 位只判 `r0>0` | 传感器未插/加热丝断时通道**静默失效、却仍报"就绪"**，状态机也不置 `PATROL_FLT_SENSOR` → 漏报 | **待修**（丢弃无效样本；样本数为 0 时不收尾并置故障位） |

| B3 | `App/Task/app_tasks.c` + `control.c:69-70` | 自研 `in.hwFault` **只看低压**；"被拿起/倾角超限"由厂商在中断里直接关电机，**不经过锁存、不置 fault、不发事件** | 上位机看到"正常巡航"，实际电机已被关 → **监控与执行器脱节**（铁律 29 的另一半） | **待修**（用 `bs.vendorStop`/`bs.angle` 派生 `tiltFault`/`pickedUp` 进状态机） |
| B4 | `App/Task/app_tasks.c`（`s_cfg` 跨任务） | `s_cfg` 由 CommTask 整体覆盖，GasTask/TaskTask/UiTask 同时读，**无保护** | 0x23 下发那一拍可能出现字段新旧混搭 → 阈值/确认数用错 | **待修**（短临界区或双缓冲+序号） |
| B5 | `App/Task/app_tasks.c:731-758` | `App_GetGas/GetPatrol/GetDiag` 用 `taskENTER_CRITICAL` 包住**含浮点与几十个字段**的区间；而 `taskENTER_CRITICAL` **挡不住**优先级 0/1 的中断，真正竞态的写者也没被保护 | 临界区只贡献延迟（可能压后 USART 接收 → ORE 计数虚高），**同步是假象** | **待修**（生产者拍快照，getter 只读） |
| B6 | `App/Task/app_config.h:127` + `patrol.c:277-336` | `CFG_WAYPOINT_SPACING_MM=0` 使 `Odom_WaypointReached()` 恒 0，而 PATROL/RETURN **只靠它推进**、无时间兜底 | 永不返航；30 min 后超时 → 误报 HWFAULT | **待修**（加时间兜底，或明确"未配置"语义） |
| B7 | `App/Sensor/dht11_hw.c` 读失败路径 | 成功路径没有把 PA7 释放回输入（失败路径才释放） | PA7 长期推挽输出高，与传感器开漏并存 → 电平争用 | **已修**（随 A3 一并整段重构，`dht11_pin_in()` 在成功路径同样执行）|
| B8 | `System/usart/usart.c:32-49` | 新增的 TX 互斥**包住**厂商无超时的 `while(TXE)` | 一次 printf 卡死 → 永久持锁 → `CommLink_Send`(`portMAX_DELAY`) 阻塞 → **500 ms 失联安全停车失效**（当前无运行期 printf，属潜在） | **待修**（给 `_write` 加超时；RTOS 下禁止 printf 进链路）|

### C 组：隐患 / 一致性（记录在案，暂不动）

- **C1** `App/Sensor/sensor_adc.c`：起转换前不清 EOC，理论上可能读到上一拍的值（需实测确认）。
- **C2** `App/Task/odom.c:54`：中断 `+=` 与任务侧清零非原子（当前间距=0 未启用）。
- **C3** `App/Comms/comm_link.c:136`：发送超时是**循环次数**而非**时间预算**，取值可能达数十 ms/字节。
- **C4** `comm_link.c:44`：`xSemaphoreCreateMutex()` 失败时锁静默失效（两处同时写 USART）。
- **C5** `Drivers/BSP/NRF24L01/24l01.c:56`：把 `PC4` 配上拉输入；一旦启用 NRF，超声波 TRIG 会被改成输入 → 测距恒 0（**必须在启用前挪脚**）。
- **C6** `System/delay/delay.c`：`delay_us` 在 DWT 未使能时**静默返回**（无任何报错）。
- **C7** `control.c` 的 `Turn_Kp/Turn_Kd` 默认 52/0.5 与厂商逐位一致；`sys.h` 删掉的 `Roll` 已在 `mpu6050.h` 声明。
- **C8** `oled.c` 软 SPI 位间加可调延时（`OLED_BIT_DELAY_LOOPS`，默认 8）：GCC -O2 编出的翻转速度可能超过 SSD1306 的 SCL 上限（**现象正是"文字全挤进第 0 页"**）。**已在代码里预留**，待上板用 0x15 的写计数判别后再定值。

### D 组：已独立核对确认「没问题」

- **控制中断 `control.c`、OLED 驱动 `oled.c`、字库 `oledfont.h`**：与厂商原版**逐行相同**（去注释空白后 175/175/197 行全同）→ "规范改造把厂商逻辑改坏了"这个担心**不成立**。
- **参数映射链**：`ParamSet` 字段序 → `Board_SyncPidParams` 形参 → 厂商全局量 → 协议 ID `0x01~0x07`，**四处一致**，无静默串位。
- **安全链每一环都有真实读者**（含 `App_MotorDisable` 是 `volatile` 原子 store、急停有不等 100 ms 的立即通道）。
- **时间比较**：73 处 `Ms` 比较全部是无符号差值形式，未发现 `now > last + timeout` 写法。
- **协议解帧边界**：长度超限/为 0/数据段含 `0xAA`/CRC 失败重同步/环形缓冲溢出，均有断言覆盖。
- **持久化**：扇区不重叠（我们 `0x08040000` vs 厂商 `0x08020000`）、魔数+个数双校验、回读逐字段比对。
- **厂商文件 22 个归一化后 0 差异**（`motor.c`/`encoder.c`/`exti.c`/`adc.c`/`ioi2c.c`/DMP 全套…）；头文件只有守卫改名。

## 4. 明天上板的动作顺序（每一步都"一次砍掉最多候选"）

| # | 做什么 | 期望 | 能收口什么 |
|---|---|---|---|
| 1 | **烧含 0x15 的新 hex**，有线链路读 0x15：电压 / `flagShow` / `flagPage` / **OLED 写计数差分** / 四个任务 tick | 电压 900~1260、`flagShow=0`、写计数 ≈5120 B/s、四个 tick 都在涨 | OLED 是"没画"还是"画错"；哪个任务死了；B2 的电压值；B6 的进度 |
| 2 | 量 **PB1 与 J17/SW2** 的直流电压，与 0x15 的电压三方对照 | PB1 ≈ 电池/11 | B2 收口：真欠压 / ADC 通路异常 / 判据过宽 |
| 3 | 示波器看 **PC13(SCL)/PC0(DC)**；同时给 `J13` 的 AO 脚外接已知电压看 0x14 raw | 有连续时钟；外接 3.3 V → raw≈4095 | C8 定值；ADC2 通路是否无辜 |
| 4 | 倾斜车体看 **CN1 pin3/4、CN2 pin3/4** 是否有 PWM 变化 | 有占空比变化 | A5/A1：`Turn_Off` 是否挡住输出、解锁后能否恢复 |
| 5 | 按 ①②③④ 的结论**一次只改一处** | — | 避免把"本来就存在的"和"新引入的"混在一起 |

**★ 提醒**：即使修好 A2，`Flag_Stop` 上电默认仍是 1（厂商设计）——
**必须显式使能**（`0x20 enable=1` 或 `0x21 task=PATROL`）电机才会输出；否则会误以为"还是不动"。

## 5. 尚未收口的存疑项

| 存疑 | 缺什么 |
|---|---|
| A1 是"有意留空"还是"回归" | `docs/design_firmware/程序说明文档.md` 只写了 0x20 → `Patrol_Command`，没写"运动输出待接"；需确认 B 阶段计划里的意图（**但风险不变：不接就没有自主行进**） |
| DHT11 实际失败率 | 需要真机的成功/失败计数（建议顺手进 0x15 的 statusBits） |
| `CFG_TX_TIMEOUT_LOOPS` 真实耗时 | 需反汇编数该循环的指令数 |
| C1（EOC 陈旧） | 需上电后连续两帧 0x14 的 raw 对照 |
| 屏型号（SSD1306 / SH1106） | 屏排线丝印或换屏试验（SH1106 需把列低地址改为 `0x02`） |

## 6. 当前台架配置（2026-10-13 实测，随进度更新）
