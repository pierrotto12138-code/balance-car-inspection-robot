## 1. 系统概述与技术选型

### 1.1 机器人要完成的三个功能（任务书要求）

| # | 功能 | 本固件的实现 |
|---|---|---|
| 1 | 就近完成巡检与研判、超阈值声光报警 | 双路 MQ + DHT11 采集 → Rs/R0 与温湿度补偿 → 多帧确认 + 迟滞研判 → 蜂鸣器（`PC5`）+ OLED |
| 2 | 状态/进展/信息**上传**监控系统 | 0x10 姿态 / 0x11 运动 / 0x12 任务 / 0x13 事件 / 0x14 环境气体 / 0x1F 心跳 |
| 3 | 监控系统**下发**指令远程控制 | 0x20 运动 / 0x21 任务 / 0x22 模式 / 0x23 巡检参数 / 0x24 PID 调参 / 0x2F 紧急停机 |

### 1.2 技术选型与理由

| 项目 | 选择 | 理由 |
|---|---|---|
| 调度 | **混合式**：控制留在 MPU6050 中断，其余进 **FreeRTOS V11.1.0** | 平衡车对控制时序极敏感；不拿已调好的 PID 去冒险，同时满足任务书的 RTOS 要求 |
| 姿态算法 | **卡尔曼滤波**（`Way_Angle=2`） | 厂商基线默认，实车实测最佳 |
| 固件库 | **ST 标准外设库（FWLIB）** | 沿用厂商工程与已验证驱动 |
| 构建 | **arm-none-eabi-gcc + Makefile** | 不使用 Keil（决策 34）；已实测可构建并直接产出 `.hex` |
| 通信 | 自研帧协议（`0xAA55` + 命令字 + 长度 + **CRC-16/MODBUS**），蓝牙 SPP 115200 8N1 | 按巡检需求定制、带校验、可解析 |
| 气体量纲 | **主链路 `Rs/R0` 相对量**，ppm 作估计值 | 绝对浓度精度不可靠；泄漏定位要的是灵敏度与相对比较（决策 18）|

> 只有 `control.c`（中断，每秒 100/200 次）与 `board_state.c` 两处会写它。

## 3. 任务划分说明

### 3.1 两个中断（时序与厂商基线**完全一致**）

| 中断 | 抢占优先级 | 触发 | 职责 | 是否调用 RTOS API |
|---|---|---|---|---|
| `EXTI15_10_IRQHandler` | **1** | MPU6050 INT（PB15 下降沿） | 5 ms：姿态/遥控/电池；10 ms：编码器 + **三环 PID** + PWM + 保护 | **否**（绝不）|
| `USART2_IRQHandler` | **0** | 蓝牙字节到达 | **只把字节推进环形缓冲**（含 ORE 处理） | **否**（绝不）|

> ★ 这两个优先级都**高于** `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY(5)`，
> 因此它们**永远不会被调度器延迟**（控制节拍得以保住），但也**绝不能调用 RTOS API**。
> 该不变量由 `tools/fw_prep/check_isr_safety.py` **静态核验**（编译器不会报，上板才炸）。

### 3.2 四个 FreeRTOS 任务

| 任务 | 优先级 | 栈（字） | 周期 | 职责 | 主要输入 → 输出 |
|---|---|---|---|---|---|
| **CommTask** | 3 | 384 | 20 ms | ① 排空环形缓冲并解帧；② 处理下行指令（0x20~0x24、0x2F）；③ 排空事件队列发 0x13；④ 20 Hz 发 0x10/0x11/0x12，5 Hz 发心跳 | 环形缓冲（字节）→ 协议帧；事件队列 → 0x13 |
| **GasTask** | 2 | 384 | 50 ms 轮询；采样周期按档位 1 s / 200 ms | 读 DHT11（1 Hz）+ 双路 ADC（8 次平均）→ 换算 → 更新通道状态 | ADC2/PA5/PA6、PA7 → `GasChannel` |
| **TaskTask** | 3 | 320 | 100 ms | 组装 `PatrolInput` → 推进状态机；阈值研判（多帧确认 + 迟滞）；决定采样档位 | 通道状态 → 阶段/事件/安全停车 |
| **UiTask** | 1 | 512 | 100 ms | OLED 刷新（`APP_Show`/`oled_show`）+ 蜂鸣器报警 | 报警状态 → 声光 |

> 栈按"最坏路径"估：UiTask 最大（OLED 刷屏调用链深）；实测可用 `uxTaskGetStackHighWaterMark()` 复核。
> 内核 heap = **24 KB**（heap_4），4 个任务栈 + 定时器/空闲任务栈都从这里分配。

### 3.3 共享资源与保护方式（"临界区/互斥保护"的落地）

| 共享资源 | 写 | 读 | 保护方式 |
|---|---|---|---|
| USART2 **发送** | CommTask（协议帧）、UiTask（`printf`） | — | **互斥量** `CommLink_LockTx/UnlockTx`（否则两条报文交错成乱码）|
| USART2 **接收** | USART2 中断 | CommTask | **SPSC 环形缓冲**（512 B；中断只塞字节，无需关中断）|
| 姿态/编码器/电压全局量 | 控制中断 | CommTask / TaskTask / UiTask | **经 `Board_ReadRaw()` 短临界区整块读取**（仅用于上报/显示，不参与控制；临界区由 board_state 内部管理）|
| 厂商"停止标志" `Flag_Stop` | 控制中断（保护逻辑）、`Board_WriteVendorStop()` | 控制中断 | **写只在两处**：`control.c`（中断）与 `board_state.c`；权威是任务侧的 `App_MotorDisable`（决策 47/53）|
| PID 参数（`Balance_Kp` 等） | CommTask（0x24 调参） | 控制中断 | **经 `Board_SyncPidParams()` 写入**（对齐 float 写在 Cortex-M4 上是单指令，原子）|
| ADC | 控制中断用 **ADC1**（PB1 电池） | GasTask 用 **ADC2**（PA5/PA6） | **物理分开**：任务侧临界区挡不住高优先级中断，只能拆硬件通道 |
| OLED（软件 SPI） | UiTask | — | 仅一个任务访问，无需保护 |
| 毫秒延时（`delay_ms`） | — | 所有任务 | **回调注入**：`App_Start()` 注册 `Delay_SetMsHook()` → `vTaskDelay`；未注册（启动阶段/裸机）走 DWT 忙等 |

> **设计原则**：能"不共享"就不共享（ADC 拆通道、串口收/发分离），
> 必须共享的用最短临界区或一个互斥量；**中断里绝不调用 RTOS API**。

### 3.4 调度时序（示意）

```
时间 ──────────────────────────────────────────────────────────────►
控制中断   │5ms│    │10ms│   │5ms│    │10ms│   ...   每 5 ms 一拍，永不缺席
CommTask        │20ms│      │20ms│      │20ms│        解帧 + 上行
GasTask         │50ms 轮询 ... 每 1 s 真正采集一次（异常时 200 ms）
TaskTask        │100ms│         │100ms│               状态机
UiTask          │100ms│              │100ms│           OLED + 蜂鸣器
```

## 4. 关键流程图

### 4.1 上电初始化

```
main()
 ├─ delay_init(168)              → 使能 DWT CYCCNT（延时不再占用 SysTick）
 ├─ uart_init(128000)            → USART1（调试/DataScope）
 ├─ NVIC_PriorityGroup_4         → FreeRTOS 要求 4 位全作抢占优先级
 ├─ LED / KEY / OLED 初始化
 ├─ TIM3_Cap_Init / TIM8_Cap_Init → 超声波（PB0 捕获）/ 航模遥控
 ├─ Encoder_Init_TIM2 / TIM4      → 左右编码器
 ├─ uart2_init(115200)            → ★ 协议链路（蓝牙）
 ├─ delay_ms(500)                 → 等系统稳定
 ├─ IIC_Init → MPU6050_initialize → DMP_Init
 ├─ Adc_Init()                    → ADC1（电池，PB1）
 ├─ CAN1_Mode_Init
 ├─ MiniBalance_PWM_Init(8400)
 └─ MiniBalance_EXTI_Init()       → ★ 控制中断从此开始跑（5 ms/10 ms）
          │
          ▼
     App_Start()  ──►  CommLink/Proto/SensorAdc/Buzzer/Gas/Patrol 初始化
                  ──►  xTaskCreate ×4
                  ──►  Delay_SetMsHook(app_delay_ms)   ← ★ 之后 delay_ms() 走 vTaskDelay
                  ──►  vTaskStartScheduler()   ← 不返回
```

> ★ **延迟钩子（决策 53）**：`System/delay` 不许反向依赖 App，所以"让出 CPU 的毫秒延时"
> 由 App 在这里**注入函数指针**；钩子注册 ⟺ 调度器已启动，因此注册之前的 `delay_ms()`
> 仍走 DWT 忙等，行为与原来完全一致。删除钩子即回到"纯裸机"语义（`USE_RTOS=0` 构建里根本没有它）。

### 4.2 控制中断（**厂商原始逻辑，未改动**）

```
EXTI15_10_IRQHandler()                        ← MPU6050 INT，下降沿
  if (INT == 0) {
      清 EXTI 标志
      Flag_Target = !Flag_Target              ← 交替出 5 ms / 10 ms 节拍
      维护 50 ms 软件延时标志
      if (Flag_Target == 1) {   ── 5 ms 分支 ─────────────────────────
          Get_Angle(卡尔曼)                   姿态
          Get_MC6()                           航模遥控
          Flash 参数回读（条件触发）
          电池电压采样 → 100 次平均 → Voltage
          return                              ★ 5 ms 到此结束
      }
      ── 10 ms 分支 ────────────────────────────────────────────────
      读编码器（TIM2/TIM4）
      Get_Angle(卡尔曼)
      Read_Distane()                          超声波
      Balance_Pwm = balance(...)              直立环 PD
      Velocity_Pwm = velocity(...)            速度环 PI（含积分限幅 ±10000）
      Turn_Pwm = turn(...)                    转向环 PD（Turn_Kp/Turn_Kd 可在线调）
      Moto1/Moto2 合成 → Xianfu_Pwm(±8200)    限幅
      Pick_Up / Put_Down 检测
      Turn_Off(倾角 ±40°、电压 <11.10 V) → Set_Pwm
      Led_Flash / Key 扫描
  }
```

```
      │                                        ├─ 5 Hz：0x1F 心跳

      │                                          └─ 等 TC 后释放互斥量
      ├─ CRC 通过 → on_frame() 分派
      │      ├─ 0x20/0x21/0x22/0x2F → Patrol_Command()
```


### 4.5 巡检状态机迁移

```
                    ┌──────────┐
        上电 ──────►│ 0x00 初始化│──(自检完成, 事件0x01)──┐
                    └──────────┘                        ▼
                                              ┌────────────────────┐
                                              │ 0x01 预热           │
                                              │ 等待: 预热时长 + R0 标定│
                                              └─────────┬──────────┘
                                          (事件0x07 预热完成/传感器失效)
                                                        ▼
      ┌────────────────────────────────────────►┌──────────────┐
      │                                          │ 0x02 待机     │
      │                                          └──────┬───────┘
      │                        收到 0x21 任务=自主巡航(0x01)，事件0x02
      │                                                 ▼
      │    ┌───────────────────────────────────►┌──────────────┐
      │    │        (报警解除 + 驻留时长到)      │ 0x03 自主巡航 │
      │    │                                    └──┬────────┬──┘
      │    │                    气体报警上升沿      │        │ 走完全部巡检点
      │    │                  (事件0x06, 5 Hz)     ▼        ▼
      │    │                            ┌──────────────┐  ┌──────────────┐
      │    └────────────────────────────│ 0x04 异常研判 │  │ 0x05 返航     │
      │                                 └──────────────┘  └──────┬───────┘
      │                                                          │ 到位(事件0x03)
      │                                                          ▼
      │                                                   ┌──────────────┐
      │                                                   │ 0x06 完成     │
      │                                                   └──────────────┘
      │
      └──── 0x07 故障 / 安全停车 ◄──── 以下任一（事件0x04）
                                    · 500 ms 未收到任何下行帧（失联）
                                    · 收到 0x2F 紧急停机
                                    · 硬件故障：电压 <11.10 V / 倾角超限（事件0x05）
                                    · 任务总超时（默认 30 min）
              ★ 安全停车**锁存**：链路恢复不自动起步，
                必须由 0x21 任务 或 0x20 使能显式解除（急停只能靠重下任务）
```

## 5. 通信协议实现说明

（协议定义见 [`docs/protocol/communication_protocol.md`](../protocol/communication_protocol.md)，此处说明**实现**）

### 5.1 帧结构与 CRC

```
 0    1    2      3      4     5 ...... 5+N-1   5+N   6+N
┌────┬────┬────┬──────┬──────┬──────────────┬─────┬─────┐
│0xAA│0x55│命令│ N低  │ N高  │   数据段 N B  │CRC低│CRC高│
└────┴────┴────┴──────┴──────┴──────────────┴─────┴─────┘
             └────────── CRC 覆盖范围（偏移 2 起，3+N 字节）──────────┘
帧总长 = 7 + N；长度与 CRC 均为**小端**
CRC-16/MODBUS：多项式 0xA001、初值 0xFFFF、输入/输出反射
```

实现要点：
- `crc16.c` 同时提供**一次性**与**增量**两个入口。解帧时用增量版
  （`update(0xFFFF, head, 3)` → `update(crc, data, N)`），**省掉一块 259 B 的拼接缓冲**，也没有 static 状态；
- 0x24 的参数值是 IEEE-754 单精度，按小端位型传输（`Proto_PutF32/GetF32`）。

### 5.2 命令字与实现位置对照

| 命令 | 名称 | N | 打包/解包函数 | 发送/处理位置 |
|---|---|---|---|---|
| 0x10 | 姿态数据 | 12 | `Proto_Pack/Unpack_Pose` | CommTask（20 Hz）|
| 0x11 | 运动状态 | **9** | `Proto_Pack/Unpack_Motion` | CommTask |
| 0x12 | 任务状态 | 5 | `Proto_Pack/Unpack_TaskState` | CommTask（`Patrol_FillTaskState`）|
| 0x13 | 事件告警 | 5 | `Proto_Pack/Unpack_Event` | CommTask（排空事件队列）|
| 0x14 | 环境与气体 | 16 | `Proto_Pack/Unpack_EnvGas` | `SensorReport_FillEnvGas` → CommTask |
| 0x1F | 心跳 | 0 | — | CommTask（5 Hz）|
| 0x20 | 运动控制 | 5 | `Proto_Unpack_MotionCmd` | `Patrol_Command` |
| 0x21 | 任务指示 | 2+2k | 直接取 `data[0]` | `Patrol_Command` |
| 0x22 | 控制模式 | 1 | — | `Patrol_Command` |
| 0x23 | 巡检参数 | 12 | `Proto_Unpack_SurveyCfg` | `on_frame`（回 0x12 确认）|
| 0x24 | PID 调参 | 6 | `Proto_Unpack/Pack_PidTune` | `on_frame`（写全局量 + **回读确认**）|
| 0x2F | 紧急停机 | 0 | — | `Patrol_Command`（安全停车并锁存）|

> ⚠️ **协议表里 0x11 原写 N=11，与字段清单（2+2+2+2+1=9）矛盾**，已由本项目的
> "文档自洽性检查"发现并修正为 **9**（见 §8.3）。

### 5.3 解帧状态机（含容错）

```
        ┌─────────┐ 0xAA  ┌─────────┐ 0x55  ┌─────┐    ┌───────┐   ┌───────┐
        │ HEADER0 │──────►│ HEADER1 │──────►│ CMD │───►│ LENLO │──►│ LENHI │
        └─────────┘       └─────────┘       └─────┘    └───────┘   └───┬───┘
             ▲                 │ 0xAA（兼容 AA AA 55）                    │
             │                 └──────────┐                              │ N>256 → 丢整帧
             │                            ▼                              ▼
             │                       （留在 HEADER1）          N==0 → CRCLO ／ N>0 → DATA
             │                                                      │
             │        ┌────────┐   ┌────────┐   ┌────────┐          │ 收满 N 字节
             └────────│ 通过    │◄──│ CRCHI  │◄──│ CRCLO  │◄─────────┘
                      └────────┘   └────────┘   └────────┘
                       投递回调      重算 CRC
                                    │ 不符 → 丢整帧；若该字节是 0xAA 则当作下一帧帧头（不漏帧）
```

容错规则（与上位机 `host/src/protocol/codec.cpp` **逐条一致**）：
1. `AA AA 55` 前缀可识别；
2. 长度 > 256 → 整帧作废并重新同步（防异常长度撑爆缓冲）；
3. CRC 不符 → 丢弃整帧，但**当前字节若为 0xAA 则保留为下一帧帧头候选**（避免连带丢帧）；
4. **单帧接收超过 100 ms 未完成 → 复位状态机**（`Proto_Feed` 的 `nowMs` 参数；时间基由调用方注入，故该逻辑可在 PC 上被测到）。

### 5.4 与上位机的一致性如何保证

| 手段 | 说明 |
|---|---|
| **共享测试向量** | [`docs/protocol/test_vectors.json/tsv`](../protocol/test_vectors.json)：CRC **4** + 帧 **16** + 流式 **6** 条，由**独立的 Python 实现**生成（决策 36）|
| **三方交叉验证** | ① Python 独立实现；② **C 侧真实代码**（编译 `host/src/protocol/*.cpp` 运行复算）；③ 固件实现（原生单测）——三者结果完全一致 |
| **协议先行** | 字段/命令字改动必须**先改协议文档**再改代码（`0x11` 长度修正、`0x24` 扩展 ID 都走这个流程）|

### 5.5 ★ 给上位机（C）的数据接口

**（1）两条对等链路**（决策 45）

| 链路 | 端口 | 速率 | 用途 |
|---|---|---|---|
| `COMM_LINK_BT` | USART2（PA2/PA3，蓝牙 SPP） | 115200 8N1 | **主链路**：演示、验收、上位机正常连接 |
| `COMM_LINK_WIRE` | USART1（PA9/PA10）= **板载 MicroUSB/CH340G** | 115200 8N1 | **有线调试链路**：实验室调试、PID 整定（**直接插板上 USB**；与烧录同一串口，调参时关掉 FlyMcu）|

两条链路**跑同一套协议**：收到帧就处理，回复**原路返回**（`0x12` 确认、`0x24` 回读等）；
而**周期上报**（0x10/0x11/0x12/0x14/0x1F）与**事件告警**（0x13）**两条链路都发** —— 谁连上都能看到数据、都不会漏事件。

**（2）上位机可直接读到的量**（都在周期上行帧里，无需额外查询）

| 帧 | 字段 | 含义 / 单位 | 来源 |
|---|---|---|---|
| 0x10 | 俯仰角 / 角速度 / 转向角速度 | 0.01° / 0.01 dps | 控制中断（卡尔曼）|
| 0x11 | 左/右轮速 | **mm/s**（按 `app_config.h` 的轮径与线数换算）| 编码器 TIM2/TIM4 |
| 0x11 | PWM | 左右 PWM 平均值（含符号）| `Moto1/Moto2` |
| 0x11 | 超声波距离 | cm | TIM3 输入捕获 |
| 0x11 | 避障状态位 | bit0/1 = 左/右红外（底板 DNP，当前恒 0）| — |
| 0x12 | 任务 ID / 阶段 / 完成度 / 巡检点 / 异常标志 | 见协议 §3.2 | `patrol.c` |
| 0x13 | 事件码 + 时间戳 | ms | 状态机事件队列 |
| 0x14 | 双路 ADC 原始值 / ppm×10 / 温度 / 湿度 / 就绪位 / 采样档位 | 见协议 §3.1 | `sensor_report.c` |
| 0x1F | 心跳 | 用于链路保活判定 | CommTask |

**（3）机器人内部还有一组只读接口**（`App/Task/app_api.h`，供后续工具与上一级软件复用）

| 接口 | 内容 |
|---|---|
| `App_GetTelemetry()` | 姿态、角速度、编码器计数、**轮速 mm/s**、PWM、超声距离、电压、是否被保护停车 |
| `App_GetGas()` | 双路 ADC 原始值、**Rs/R0**、`R0`、ppm×10、报警标志、温湿度、就绪位、采样档位 |
| `App_GetPatrol()` | 阶段、任务 ID、完成度、巡检点、异常标志、**安全停车原因** |
| `App_GetDiag()` | 两条链路的收字节/丢弃/ORE 计数、解帧统计、**四任务心跳**、**FreeRTOS 剩余堆与历史最小值**、调参模式 |
| `App_SetPidParam()/GetPidParam()/SavePidParams()/LoadPidParams()` | PID 参数读写与持久化 |
| `App_SetTuningMode()` | 调参观测模式开关 |

> 线程安全：这些 getter 自带短临界区，可**从任意任务**调用；**不要在高优先级中断里调用**。
> `App_GetDiag()` 的"剩余堆 + 四任务心跳"是排障利器：堆持续下降 = 内存泄漏；某任务心跳不涨 = 该任务被饿死。

**（4）有线 PID 调参流程**（板子到货后由 B 执行；C 也可照此实现界面）

```text
① USB-TTL 接 PA9/PA10（USART1），115200 8N1
② 发 0x24{ID=0xFD, value=1.0} → 进入调参观测模式
      机器人回 {ID=0xFD, value=1.0} 确认；此后 **100 Hz** 上报 0x10/0x11（仅有线链路）
③ 发 0x24{ID=0xFF}            → 全量回读 7 个参数，确认当前值
④ 发 0x24{ID=0x03, value=85.0} → 改 Velocity_Kp；机器人回该参数**实际生效值**
      （改动立即生效：控制中断直接读这些全局量）
⑤ 观察 ② 的 100 Hz 数据，重复 ④ 直到满意
⑥ 发 0x24{ID=0x00}            → 存入 Flash；机器人回 {ID=0x00, value=0.0} 表示成功
⑦ 发 0x24{ID=0xFD, value=0.0} → 退出调参观测模式（恢复常态 20 Hz 上报）
```

> 参数持久化实现要点（`param_pack.c` + `param_store.c`）：**float 位型存储**（不做定点缩放、无精度损失）、
> 带 magic + 参数个数 + **数值合理性校验**（Flash 位翻转产生的离谱值会被拒绝）、写入后**当场回读校验**；
> 存储区在扇区 6（`0x08040000`），**不复用**厂商在 `0x08020000` 的旧存储区。
> 打包/解包有**原生单测**（29 条断言），专门覆盖"存了却读不回来"这一经典坑。

以上三个环的增益均可由 **0x24 在线修改**（掉电保存由 Flash 机制支持）。

### 6.2 气体传感（MQ-2 / MQ-135）

```
ADC2 原始值(0~4095)
   │  Vadc = raw × 3300 mV / 4095
   ▼
反分压：Vao = Vadc × (R10+R11)/R11 = Vadc × 25/15      ← 板上 10k 串联 + 15k 对地
   │
   ▼
Rs = (VCC × RL) / Vao − RL                             VCC=5 V，RL 需实测（默认 10 kΩ）
   │
   ▼
ratio = Rs / R0                                        R0 由清洁空气标定：R0 = Rs_air / 9.83(MQ-2) 或 / 3.6(MQ-135)
   │  温湿度补偿（默认关闭）：ratio_corr = ratio / factor
   │      factor = 0.00035·t² − 0.02718·t + 1.39538 − (h−33)·0.0018
   ▼
8 点滑动平均 → ppm = a · ratio^b（估计值；MQ-2 取 LPG，MQ-135 取 NH4）
```

**关键设计**：
- **补偿用"除法"而非"叠加"**：该公式在参考点（≈19.4 ℃/33 %RH）≈ **1.0**，按叠加用等于给 ratio 白加 1.0，物理上讲不通（决策 39）；且**默认关闭**，需实测复核后再开。
- **ppm 只作估计值**（决策 18）；**上报前必须饱和钳位**到 uint16 上限 —— 幂律在 ratio 很小时可达千万级，不钳位会回绕成小数字，恰好把危险工况报成"浓度很低"（决策 40）。
- **研判**：连续 `confirmFrames`（默认 3）帧超阈值才确认报警；跌到阈值的 **90%** 以下才解除（迟滞）。
- **自适应采样**：常态 1 Hz；进入异常研判或处于报警态 → **5 Hz**（决策要求的"异常驱动"）。

### 6.3 温湿度（DHT11）

- 单总线时序：拉低 20 ms → 等响应 → 40 bit 按时长判 0/1（采样点取低电平结束后 40 µs）；
- **每步都有超时上限**，传感器不在也不会死等；读失败**重试 3 次**；
- 解析层独立（`dht11.c`）：校验和 / 全 0 / 全 0xFF / 超量程都判为不可信并**丢弃整帧**；
- 读不到只置"传感器失效"标志并自动停用补偿，**不阻塞巡检任务**（决策 41）。

### 6.4 巡检点判据（编码器里程，**不依赖红外**）

底板的红外避障两路（`PB12`/`PC1`）是 **DNP（留焊盘不留排针）**，实物上没有，
所以巡检点判据用**编码器里程**（决策 49），不需要任何额外器件：

```
控制中断 10 ms 分支：Encoder_Left/Right 是**本拍增量** → Odom_AddCounts(左,右)   （纯整数加法）
TaskTask 100 ms：    Odom_WaypointReached() → PatrolInput.waypointReached
```

- 里程按**微米整数**累积（1 计数 ≈ 135 µm），中断里没有浮点、没有除法；
- 左右取**绝对值平均**，单轮打滑不会把里程翻倍；
- 跨过一个间距**只报一次**到位，之后自动开始下一段；
- 间距在 `app_config.h` 的 `CFG_WAYPOINT_SPACING_MM` 配置，**当前是 0 = 暂未启用**
  （`waypointReached` 恒为 0，车按指令推进）—— 量出场地标线间距后改这一处即可。
- 若以后补焊红外，只需把 `waypointReached` 换成红外判据，**状态机不用改**（它只认这一个布尔输入）。

### 6.5 测距与避障

- 超声波 HC-SR04：TRIG = **PC4**（板上实际，基线源码是 PC2，已改），ECHO = PB0（TIM3_CH3 输入捕获）；
- 红外避障两路（PB12 / PC1）因底板 **DNP 未装排针**，固件保留引脚定义、默认不启用（决策 30）。

## 7. 安全机制

| # | 机制 | 触发条件 | 动作 | 来源 |
|---|---|---|---|---|
| 1 | 倾角保护 | 相对机械中值 > ±40° | 关电机（`Turn_Off`） | 基线 |
| 2 | 低电压保护 | 电池 < **11.10 V**（`Voltage<1110`，单位 0.01 V） | 关电机 | 基线 |
| 3 | PWM 限幅 | 输出 > ±8200 | 截断 | 基线 |
| 4 | 积分限幅 | 速度环积分 > ±10000 | 截断 | 基线 |
| 5 | 拿起/放下检测 | Z 轴加速度 + 倾角 + 编码器 | 拿起关电机、放下恢复 | 基线 |
| 6 | **通信失联保护** | **500 ms 未收到任何下行帧**（且曾收到过） | 安全停车并**锁存**；`Patrol_MotorsDisabled()` → 中断强制 `Flag_Stop=1`（见下）| 新增 |
| 7 | **紧急停机** | 收到 0x2F | 立即安全停车并锁存；**只能重下任务解除** | 新增 |
| 8 | **任务超时** | 巡航超过 30 min | 任务失败 + 安全停车 | 新增 |
| 9 | **故障上报** | 上述任一 | 事件 0x04/0x05 + 0x12 异常标志 | 新增 |
| 10 | RTOS 故障钩子 | 任务栈溢出 / 堆耗尽 | LED 常亮 + 关中断停住（便于调试器定位） | 新增 |

> 安全停车是**锁存**的：链路恢复不会自动重新起步，必须由上位机重新下发任务或使能
> —— 避免"信号一抖车就自己冲出去"（决策 41）。
>
> ★ **决策 47 补齐了这条链路的最后一环**：状态机算出的"该停车"必须**真的作用到电机**。
> 实现：`TaskTask` 把 `Patrol_MotorsDisabled()` 写进 `App_MotorDisable`（volatile u8），
> 控制中断每拍据此**强制** `Flag_Stop=1`（厂商的 `Turn_Off()` 随即把 PWM 置 0）；
> 同时挡住两条"绕过锁存"的厂商逻辑：**单击启停**与**放下自动使能**（`Put_Down`）。
> 此前这三者互不相连，锁存只停在状态机里、电机照转 —— 是本轮复查抓到的最严重问题。

## 8. 可测试性与离线验证

### 8.1 为什么能在没有硬件时验证

把**协议、算法、状态机**三类模块写成**只依赖 `<stdint.h>` 的纯 C**，硬件与时间由调用方注入：

| 模块 | 可离线测试的原因 |
|---|---|
| `crc16.c` / `protocol.c` / `ringbuf.c` | 无 ST 依赖；解帧的**时间基由参数传入**，超时逻辑可测 |
| `gas.c` / `dht11.c` / `sensor_report.c` | 输入是 ADC 原始值与 DHT 字节，输出是数值/结构体 |
| `patrol.c` | 输入是 `PatrolInput`（含 `nowMs`），整条任务时间线可脚本化 |

### 8.3 软件测试**实际抓到的问题**（体现测试价值）

| # | 问题 | 后果（若不修） | 发现方式 |
|---|---|---|---|
| 1 | `Proto_Encode()` 把数据段写在偏移 4（应为 5） | 长度字段被数据首字节覆盖 → **上位机永远收不到有效帧**，且极难查 | 帧用例逐字节比对（12 条同时变红）|
| 2 | 协议文档 `0x11` 长度写 11，字段清单算出 **9** | B/C 两端长度不一致 → 解帧必然失败 | `gen_test_vectors.py` 的**文档自洽性检查** |
| 3 | 温湿度补偿方向的断言写反（湿度越高系数越小，除法修正后 ratio 变大） | 报告里会把补偿方向说反 | 传感器不变量测试（向量全对 → 证明是**断言**错，不是实现错）|
| 4 | 气体异常标志晚一拍清除 | 上位机会看到"巡航 + 气体异常"的自相矛盾状态，且多保持一个周期 5 Hz | 状态机时间线断言 |
| 5 | C 侧交叉验证程序因向量新增分节而崩溃 / 漏算 2 条 | 交叉验证本身失效（比没有更危险） | 交叉验证运行时异常 |
| 6 | **R0 标定永远收不了尾 → 状态机卡在"预热"**（收尾代码写在"已离开预热"的分支里，逻辑死锁）| 车永远进不了待机，**整个巡检功能不可用** | **第二轮代码复查**（通读任务层）|
| 7 | 上位机侧 `0x11` 的轮速/PWM 报的是**编码器脉冲**与常数 0，不是协议定义的 mm/s 与 PWM | 上位机画出来的速度/占空比没有物理意义 | 对照协议字段定义做"接口清理"时发现 |
| 8 | `0x23` 收到后**只更新参数、没回 0x12 确认**（协议 §4.1 明确要求）| 上位机无法确认参数是否生效 | 同上 |

## 9. 编译、烧录与运行

### 9.1 编译（PC 端，不需要 Keil）

```powershell
cd <仓库根>/firmware
make                # 默认带 FreeRTOS；产出 build/MiniBalance.{elf,hex,bin,map}
make USE_RTOS=0     # 纯裸机对照（与厂商基线行为一致，用于二分定位）
make size           # 看 Flash / RAM 占用
```

### 9.2 烧录

| 方式 | 步骤 |
|---|---|
| **串口 ISP（FlyMcu，推荐）** | 控制板 MicroUSB 接电脑（板载 CH340G，含 DTR/RTS 自动 ISP）→ 选串口 → 载入 `firmware\build\MiniBalance.hex` → 开始编程 |
| **ST-Link（SWD）** | `make flash`（内部为 `STM32_Programmer_CLI -c port=SWD -d xxx.hex -v -rst`）|

`.hex` 数据区 `0x08000000 ~ 0x0800xxxx`，标准 Intel HEX，可直接烧录。

### 9.3 上电后的预期行为

1. OLED 亮起并显示（`Flag_Show=0` 时 U 板载 APP 界面）；
2. 控制中断开始跑，**小车应能正常平衡**（这是验证"未调参时与厂商基线等价"的关键一步）；
3. 500 ms 内若没有下行帧且**曾经收到过**，进入安全停车；
4. 蓝牙 115200 8N1 下，上位机连上后应能收到 20 Hz 的 0x10/0x11/0x12 与 5 Hz 心跳。

## 11. 未完成项与后续计划

### 11.1 到货后必须实测（P5）

> 📋 **逐项操作、每一项的"通过判据"与"不通过怎么查"，已整理成**
> [`../design_hardware/上板自检清单.md`](../design_hardware/上板自检清单.md)
> （上电前 → 上电 → 烧录（裸机/RTOS 对照）→ 界面 → 双链路 → 电机/姿态 → 平衡 → 标定 → 排障速查）。
> 下表只说明"为什么必须实测"。

| # | 项目 | 为什么必须实测 | 预案 |
|---|---|---|---|
| 1 | **能否正常平衡** | 验证"未调参时与基线等价"（改了 3 处：DWT 延时、Group_4、转向环增益全局化）| 先烧 `USE_RTOS=0` 版对照；不平就二分回退 |
| 2 | 蓝牙 115200 | 基线模块原为 9600，需 AT 改 | 改不了则协议波特率回退并同步 C |
| 3 | DHT11 任务上下文稳定性 | 20 ms 读窗会被控制中断打断 | 已内置重试 3 次；仍不行则改由中断捕获边沿 |
| 4 | MQ 的 **RL** 与 **R0** | 文献明确要求实测，否则 ppm 整体偏一个系数 | 万用表量负载电阻；清洁空气下多次平均标定 R0 存 Flash |
| 5 | 编码器 → 里程标定 | **`waypointReached` 目前恒为 0**（已知待接线项） | 按 1560 counts/圈 折算，实测校正 |

### 11.2 功能上已知的"留白"（不影响任务书三大功能）

- OLED 显示内容仍是厂商那几屏（未加"气体浓度/阶段"字段）——显示层扩展留到联调期；
- 红外避障代码保留但默认不启用（底板 DNP，决策 30），故 `0x11` 的避障状态位恒为 0；
- 失联事件目前复用 0x04 + 0x12 的异常标志位，**未新增专用事件码**（避免与上位机不同步，等 C 会签）；
- `0x24` 的 4 个扩展参数 ID 属**协议 v1.0-b 提案**，B 侧已实现，**待 C 会签**；
- 轮速 mm/s 依赖 `CFG_WHEEL_DIAMETER_MM`（暂定 67 mm）与 `CFG_ENCODER_COUNTS_PER_REV`（1560），
  **到货后必须实测修正**，否则轮速只是"按假设换算"的值。
