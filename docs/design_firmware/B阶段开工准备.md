### 2.4 构建产物与两种烧录方式（已定：**必须出 `.hex`**）

| 产物 | 说明 |
|---|---|
| `firmware/build/*.elf` | 调试/查符号、`arm-none-eabi-size` 看占用 |
| **`firmware/build/*.hex`** | **★ 默认产物** —— 用 `arm-none-eabi-objcopy -O ihex` 生成，起始地址 `0x08000000`，可直接给 FlyMcu |
| `firmware/build/*.bin` | 备用（部分烧录器/OTA 用） |
| `firmware/build/*.map` | 排查"Flash 装不下/RAM 溢出" |

| 烧录方式 | 做法 | 备注 |
|---|---|---|
| **① 串口 ISP（FlyMcu）** | 控制板 **MicroUSB** 线接电脑 → 选 CH340 虚拟串口 → 载入 `.hex` → 开始编程 | 板上 `DTR/RTS` 经 `Q1(8550)` 驱动 **BOOT0**，属**自动 ISP**：正常不用手动拨跳线；若进不去 BootLoader，再手动把 BOOT0 拉高后复位 |
| ② SWD（ST-Link） | `STM32_Programmer_CLI -c port=SWD -d firmware\build\xxx.hex -v` | 该命令行工具随 CubeCLT/CubeProgrammer 提供（实测 2.23），另有可借的 ST-Link；**下载后可 `-v` 校验**，更适合调 PID 时的反复烧录 |

> ⚠️ 用 ST-Link/SWD 时不要占 `PA13`/`PA14`；用串口 ISP 时 `PA9/PA10` 即被占用（原本是 DataScope 调试口，二选一）。

## 四、★ 引脚与接口基线（**以最终"改"板为准**，与源码的差异在末列）

> 原则：**底板/插座是权威**（实物丝印已核）；源码只作参考。凡与源码不一致的，固件必须按本表改。

| 模块 | 座 | 最终引脚（板上） | 与基线源码的差异 → 固件动作 |
|---|---|---|---|
| **MQ-2** | `J13` | AO→**PA5**（ADC1_IN5，经 `R10/R11` 10k/15k 分压 ×0.6）<br>DO→**PB3** | 源码无 → **新增 ADC 通道**；`PB3` 可作数字阈值输入（可选） |
| **MQ-135** | `J10` | AO→**PA6**（ADC1_IN6，经 `R12/R13` 分压 ×0.6）<br>DO→**PC3** | 同上 |
| **DHT11** | `J9` | **PA7**（`R14` 4.7k 上拉至 +3.3V） | 源码无 → 新增单总线驱动 |
| **HC-SR04** | `J5` | TRIG→**PC4**、ECHO→**PB0**（TIM3_CH3 输入捕获） | ⚠️ **源码 TRIG 是 PC2** → 必须改 `TIM3_Cap_Init()` 里的 GPIO 配置 |
| **蓝牙** | `J7` | **PA2/PA3**（USART2） | ⚠️ 源码 `uart2_init(9600)` → 改 **115200**（并去掉单字节 APP 解释） |
| **蜂鸣器** | `J18` | **PC5**，**有源、低电平响**（直连，不走 `Q1/BZ1`） | 源码用 `BZ1+Q1` 且极性相反 → **改为 GPIO 低电平触发**（决策 26） |
| **红外避障 L/R** | `J11`/`J14` | `PB12` / `PC1`（**DNP：留焊盘不装排针**） | 源码用的是 PA4 等 → **改为 PB12/PC1**，且**默认编译期关闭**（实物未装） |
| 电池电压 | — | **PB1**（ADC1_IN9，`R3/R2` 10k/1k 0.1%） | **不变**；`Voltage` 单位为 **0.01 V**，低压阈值 **1110 = 11.10 V** |
| MPU6050 | 控制板板载 | **PB10/PB11** 软件 I2C，INT→**PB15** | **不变**（控制中断源） |
| OLED | 控制板 6 针座 | `PC0`(DC)/`PC13`(SCL)/`PC14`(SDA)/`PC15`(RST)，**软件 SPI** | **不变**；与 MPU6050 **不共总线**（一个是软件 SPI、一个是软件 I2C） |
| 电机 / 编码器 | `CN1`/`CN2` | PA11/PA8 PWM、PA15/PB5、PA12/PB4、PA0/PA1、PB6/PB7 | **不变**（电机与编码器可原样插新板，固件电机部分不用改） |
| SWD | — | PA13/PA14 | **不可占用** |

**新增 ADC 通道的技术要点**（写代码前必须记住）：

1. 基线 `adc.c` 只做了 **PB1 单通道、非扫描、软件触发、采样时间 480 周期**；要读 3 路（PB1/PA5/PA6），
   最稳的做法是**保留单次转换 + 逐通道切 `ADC_RegularChannelConfig()`**，或改用**扫描 + DMA**。
2. **采样时间必须放长**（MQ 分压源阻抗 ≈ 6 kΩ）—— 480 周期已在基线用过，沿用即可。
3. 分压比 **0.6**，`3.3 V / 4096` 量化；MQ 的 `Rs` 用 `Rs = (VCC·RL)/Vout − RL`（`VCC=5 V`，**RL 必须实测**，默认 10 kΩ）。

### 12.4 两个工程决策（已记入决策记录 39/40）

1. **温湿度补偿用"除法"而不是"叠加"**：两套开源用法（MQUnifiedsensor 叠加 / GeorgK 除法）用的是**同一个公式**，而该公式在参考点≈1.0 —— 按叠加用等于凭空给 ratio 加 1.0（MQ-135 清洁空气才 3.6，等于 +28%），物理上讲不通。故采用除法，且**默认关闭**（由 0x23 的"补偿使能"控制），打开前必须实测复核。
2. **ppm×10 必须饱和钳位**：`ppm = a·ratio^b` 是幂律，ratio 很小时 ppm 可到千万级；协议字段是 uint16，**不钳位会回绕成小数字 —— 恰好把危险工况报成"浓度很低"**。已钳到 65535 并单测。

### 13.2 三条安全设计（决策 41）

| # | 设计 | 理由 |
|---|---|---|
| 1 | **500 ms 未收到任何下行帧 → 安全停车**（协议 §5） | 只在"曾经收到过下行帧"之后才判失联 —— 否则上电瞬间就停车，车根本没法用 |
| 2 | 安全停车**锁存**：链路恢复**不自动起步**，必须由指令（0x21 任务 / 0x20 使能）显式解除 | "信号一抖车就自己冲出去"在仓库里不可接受 |
| 3 | 急停（0x2F）与硬件故障（低电压/倾角）走**同一条**安全停车通道，且急停不能被 0x20 解除 | 一条通道好验证；急停需要更强的解除条件（重下任务，即人工确认） |

## 十四、P4 执行记录（2026-10-09）：FreeRTOS 任务化 —— 真正动到运行时的那一步

> 目标：把"可以并发等待"的部分（采集/通信/状态机/界面）交给 FreeRTOS，
> 同时**让 5 ms/10 ms 的控制中断时序一字不改**。

### 14.1 四个任务与两条中断的分工

| 上下文 | 频率 | 职责 | 约束 |
|---|---|---|---|
| `EXTI15_10_IRQHandler`（抢占优先级 **1**） | 5/10 ms | 姿态 + 三环 PID + PWM + 保护 | **代码零改动**；不调用任何 RTOS API |
| `USART2_IRQHandler`（抢占优先级 **0**） | 字节到达 | **只把字节推进环形缓冲** | 同样不调用 RTOS API；解帧交给 CommTask |
| `CommTask`（优先级 3，384 字栈） | 20 ms | 解帧下行 → 处理指令；排空事件队列（0x13）；20 Hz 上行姿态/运动/任务 + 5 Hz 心跳 | 唯一碰串口发送的任务 |
| `GasTask`（2，384） | 50 ms 轮询 / 1 s 或 200 ms 采样 | 双路 ADC + DHT11 + 换算 + 研判 | 采样周期由档位决定 |
| `TaskTask`（3，320） | 100 ms | 状态机推进（含 500 ms 失联停车） | 输入全部来自任务侧变量 |
| `UiTask`（1，512） | 100 ms | OLED 刷新 + 蜂鸣器报警 | 低优先级，慢也安全 |

### 14.2 ★ 共享资源清单与保护方式（"临界区/互斥保护"的落地）

| 共享资源 | 写 | 读 | 保护 |
|---|---|---|---|
| USART2 **发送** | CommTask（协议帧）、UiTask（`printf`） | — | **互斥量** `CommLink_LockTx/UnlockTx`（否则两条报文交错成乱码）|
| USART2 **接收** | USART2 中断 | CommTask | **SPSC 环形缓冲**（512 B，中断只塞字节，无需关中断）|
| 姿态/编码器/电压全局量 | 控制中断 | CommTask | **短临界区整块读取**（仅用于上报/显示；对齐 32 位读写本身原子）|
| PID 参数 | CommTask（0x24 调参） | 控制中断 | **短临界区写入** |
| ADC1（PB1 电池） | 控制中断 | — | 与任务**物理分开** |
| ADC2（PA5/PA6 气体） | — | GasTask | 同上（见 14.3 的坑）|
| OLED（软件 SPI） | UiTask | — | 仅一个任务访问，无需保护 |

> **修正了架构文档的一处旧结论**：原 `architecture.md` §3.3 说"MPU6050 与 OLED 共用软件 I2C，需要互斥量"。
> 实板核实：**OLED 是软件 SPI（PC0/13/14/15），MPU6050 才是软件 I2C（PB10/11）**，两者不共总线 →
> **不需要 I2C 互斥量**（旧结论来自 F103C8T6 那版基底）。已改写该节。

### 14.3 ★★ 本轮最要紧的一个发现：ADC 不能中断/任务共用

厂商的电池采样 `Get_battery_volt()` 是在**控制中断里**跑的，它每次都会重设 **ADC1** 的通道并软件触发。
如果 GasTask 也拿 ADC1 读 PA5/PA6，两者会互相打断：中断改了通道 → 任务拿到的转换结果属于另一个通道，
`Get_Adc()` 里"等 EOC"的循环也会被对方吃掉标志。
**任务侧的临界区挡不住它** —— 控制中断的优先级高于 FreeRTOS 的屏蔽阈值，临界区拦不住。

**处置（决策 43）**：利用 PA5/PA6 同时挂在 `ADC12_IN5/IN6` 这一事实，**把气体两路改到 ADC2**：
`ADC1 → PB1（电池，中断专用）`、`ADC2 → PA5/PA6（气体，任务专用）`。彻底不共享，比任何加锁都可靠。

### 14.4 其它关键改动

| 位置 | 改动 | 原因 |
|---|---|---|
| `System/delay/delay.c` | `delay_us/xms` 改 **DWT CYCCNT** 忙等；`delay_ms` 在调度器运行时用 `vTaskDelay` | 原版直接读写 **SysTick**，与 FreeRTOS 节拍互相破坏（任务里一次 `delay_us(40)` 就把内核节拍改了）|

| `Drivers/BSP/EXTI|USARTX` | ISR 保持原优先级（1 / 0）不变 | 这样它们**永远不会被调度器延迟**，控制节拍不受影响 |
| `App/Ui/buzzer.c` | 新增：PC5 **低电平响**（有源模块，决策 26） | 任务书要求超阈值声光报警 |
