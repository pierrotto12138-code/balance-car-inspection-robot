# 开源方案调研：与任务书相似的项目（第二轮）

> 调研日期：2026-09-23
> **本轮目标与上一轮不同**：上一轮找的是"可复用的硬件基底"（要能打板），
> 本轮找的是"**与任务书结构相似、可作参照的整套方案**"（重点看上位机怎么做、双向通信怎么设计、状态机怎么组织）。
> 检索平台：GitHub（可用）、Gitee（匿名搜索不可用）、立创开源 oshwhub（客户端渲染，不可检索）。

## 一、核心结论（先说结果）

### 1.1 没有"几乎就是任务书翻版"的项目

**一个都没有。** 差距不在选题，而在**角色完整度**：

| 类型 | 找到了什么 | 缺什么 |
|---|---|---|
| 覆盖 **A1+B+C**（硬件+固件+上位机）的 | beginner-eng、tstbswwswbst、RiceChen、cuitsj、baiyanmo | **全都缺 FreeRTOS**；或不是 F103C8T6；且都不是"平衡车 + 任务执行"组合 |
| 覆盖 **F103C8T6 + HAL + FreeRTOS** 的 | 1kelejiabing1、HadiseMousavi81、noodles-zip11 | **完全没有 PC 上位机** |
| 覆盖 **平衡车 + 上位机** 的 | RiceChen、cuitsj、drifting-cloudlet | 上位机只做**波形/调参**，没有"任务进展上报"，也没有"任务状态机" |

### 1.2 我们的任务书比社区常见项目**更完整**

**"四角色分工 + 状态上行/指令下行闭环 + 任务执行状态机"三件事同时具备的项目，检索未找到。**

具体差距：

| 任务书要求 | 社区项目普遍情况 |
|---|---|
| A1 原理图+PCB+制板 | 部分项目有（多为"只有原理图"） |
| **A2 结构方案+装配图+效果图** | ⚠️ **全体空缺**，没有任何仓库提供结构交付物 |
| B F103+HAL+FreeRTOS+Keil+PID | 有（但都缺上位机） |
| C PC 上位机（双向+监测+控制+存储） | 罕见；有的话只做波形/调参 |
| **任务执行状态机 + 任务进展上报** | 几乎无（仅概念级参照） |

> **含义**：这不是坏事。说明我们做的是一个**系统级项目**，而不是"抄一个固件就完事"。
> 也意味着 A2 和"状态机"部分**必须自研**，找不到现成可抄的。

### 1.3 数量级（据 GitHub `total_count`）

| 检索词 | 命中数 |
|---|---|
| `平衡小车 PID` | 45 |
| `平衡小车 Bluetooth` | 22 |
| `循迹小车 STM32` | 67 |
| **`平衡小车 上位机`** | **3** |
| **`上位机 平衡`** | **11**（去重后真相关约 5–6 个） |

**"平衡车 + PC 上位机"：罕见，约 5–15 个。**
**"平衡车 + 上位机 + 原理图/PCB"：极罕见，≤2 个。**

## 二、最值得看的 5 个项目（相似度 4/5）

### 2.1 beginner-eng/stm32-inspection-balance-car ⭐ 首推

https://github.com/beginner-eng/stm32-inspection-balance-car ｜ License: MIT

| 项目 | 内容 |
|---|---|
| 包含 | 固件 + **Python 上位机** + ~~PCB~~ + 文档 |
| 技术栈 | **STM32F103C8T6 + HAL**（CubeMX 生成）；无 FreeRTOS；三环串级 PID；MPU6050 |
| 通信 | **双路蓝牙**：USART1 上行 + USART3 收指令 |
| 双向闭环 | ✅ 有 |
| 相似度 | **4/5** |

> ⚠️ **更正（2026-09-23）**：实测其文件清单（965 文件），**并没有 PCB / 原理图 / Gerber**。
> 顶层只有 `1工程代码说明文档/`、`Servo_Steering_Wheeled_Car/`（固件）、
> `Upper_Computer_Program/`（上位机）和三张图片。硬件应为现成套件。
> 且注意其固件目录名为 **Servo_Steering_Wheeled_Car**（舵机转向小车），**非差速平衡车**。
> 详见 `PCB可用性核实.md`。

**最值得借鉴**：
- **上位机形态与我们的 C 角色几乎一致**：`upper_comp_ble.py` 收 BLE Notify，
  实时画环境曲线 + 轨迹散点 + 风险指数 + 电量，并 **CSV 导出**；`risk_lvl_3D.py` 做离线 3D 轨迹回放
- **双通道无线分工**（一条专上行、一条专收指令）——值得参考
- 文档目录结构 `1工程代码说明文档`
- **任务性质接近**（"巡检/环境监测"），与我们"仓储环境巡检"最像

**差在**：无 FreeRTOS（任务书硬要求）；无结构模型；任务状态机不明确。

### 2.2 tstbswwswbst/stm32-smart-car-control ⭐ 交付物组织最佳

https://github.com/tstbswwswbst/stm32-smart-car-control ｜ 无 License

| 项目 | 内容 |
|---|---|
| 包含 | 固件 + **LabVIEW 上位机** + 原理图 PNG + **完整课设文档**（任务书 PDF / 设计文档 / 报告 / 答辩 PPT）+ 成果视频 |
| 技术栈 | STM32F103C8（C8T6 核心板）；标准外设库；无 RTOS；无 PID |
| 功能 | HC-SR04 避障、定距跟随、红外循迹、麦克纳姆轮四驱、OLED |
| 通信 | **文本协议**：下发 `"low speed"` / `"avoid"` / `"obstacle avoid distance <cm>"`（以 `.` 结尾识别）；每 3 秒回传带标签状态 |
| 双向闭环 | ✅ 有 |
| 相似度 | **4/5**（选题命中"避障+跟随+循迹"三项） |

**最值得借鉴**：
- ★ **课设交付物的组织方式**——`docs/` 里任务书/设计/报告/PPT 一应俱全，`项目成果/` 放视频照片。
  **这是我们交差时最该模仿的结构**
- **极简文本协议**：`.` 结尾识别 + 3s 周期遥测 + 关键词命令 —— 实现成本最低
- 唯一把 **LabVIEW 上位机**开源出来的课设项目（任务书明确允许 LabVIEW）

**差在**：非平衡车（四轮麦轮）；无 RTOS；无 PID；无 PCB（只有原理图）；无结构模型。

### 2.3 RiceChen/Balance_Car ⭐ 唯一的"平衡车全栈"

https://github.com/RiceChen/Balance_Car ｜ 24⭐ ｜ 无 License ｜ 2021-01

| 项目 | 内容 |
|---|---|
| 包含 | `bc_upper/`（**Qt 上位机**）+ `bc_mp/`（微信小程序）+ `hardware/`（**原理图 + PCB**）+ `software/`（固件） |
| 上位机功能 | 参数设置、方向控制、**PID 输出量波形** |
| 相似度 | **4/5** —— **唯一同时有"平衡车 + 上位机 + 原理图/PCB"的仓库** |

**最值得借鉴**：
- **Qt 上位机的三区布局**：参数设置面板 + 遥控面板 + PID 波形面板 —— 正好对应任务书的
  "远程控制面板 + 状态监测面板"
- **微信小程序做第二客户端**（可作"监控系统"的加分扩展）

**差在**：MCU/HAL/FreeRTOS 页面未说明（需进仓库核实）；无结构模型；无状态机；项目较老（2021）。

### 2.4 cuitsj/BalanceCar_Inspirer

https://github.com/cuitsj/BalanceCar_Inspirer ｜ 6⭐ ｜ **GPL-3.0** ｜ 2023-08

## 三、B 角色技术栈 1:1 命中的项目

**任务书 B 角色要求：F103C8T6 + HAL + FreeRTOS + Keil + PID。**
符合的组合只有三个（均无上位机）：

| 项目 | 技术栈 | 借鉴点 |
|---|---|---|
| **1kelejiabing1/BanlanceCar** | F103C8T6 + HAL + **FreeRTOS** + 三环 PID + 蓝牙调参 + NRF24L01 | ★★ **最完整的对照**：BLE 环形缓冲解析**状态机** + 按键状态机可直接用；`遇到的问题.txt` 踩坑记录值得仿 |
| **noodles-zip11/STM32-FreeRTOS-K210-SmartCar** | F103 + HAL + **FreeRTOS**（5 任务）+ 模式 **0–4 状态机** + Flash 持久化 | ★★ **FreeRTOS 任务划分**（控制/传感/视觉/逻辑/UI）几乎可照搬；"多任务+模式状态机+参数存 Flash"是任务状态机的标准范式 |
| **HadiseMousavi81/stm32-autonomous-self-balancing-robot** | F103C8T6 + HAL + **FreeRTOS** + MPU6050 卡尔曼 + 正交编码器 | 硬件平台与 B 角色要求几乎 1:1；但无任何 PC 通信 |

## 五、协议与状态机的最佳参照

### 5.1 ChaseZhao619/RCJChassisDriver ⭐ 协议设计最值得抄

https://github.com/ChaseZhao619/RCJChassisDriver ｜ 3⭐ ｜ GPL-3.0

- STM32F407 + HAL 固件 + **Qt6 上位机** + 串口协议 + 文档
- **串口帧带 CRC**（`payload*CCCC\r\n`，115200 8N1）
- **命令式协议**：`cmd_dis` / `cmd_turn` / `cmd_dkmotor`
- ★ **下位机持续返回 `busy` 与完成事件**，App 层有"命令解析、状态机、完成事件"

> **这正是任务书"任务进展上传"该有的样子**：不是只上报数值，而是上报**任务状态机的状态变化**。

### 5.2 Alba8228/Car-ArUco

- 三端：Linux(C++) + STM32F103C8T6(Keil) + Windows C# 上位机
- **三状态机 SEARCH/TRACK/DOCK**；**16 字节状态包回传**（转向/挡位/模式）；串口 115200 + UDP
- 借鉴：**多状态机 + 定长状态包**的组合

## 七、对我们的行动建议

### 7.1 立即可用（改文档/写报告时）

| 来源 | 用在 |
|---|---|
| **tstbswwswbst** 的 `docs/` 结构 | ★ **抄它的交付物组织方式**（任务书/设计/报告/PPT/成果） |
| **beginner-eng** 的上位机面板组织 | C 角色的界面参照（曲线+轨迹+指标+CSV） |
| **ChaseZhao619** 的 busy/done 事件模型 | B 角色"任务进展上报"的设计参照 |
| **ADrownFish/RoboticUserInterface**（MIT） | C 角色若嫌自研慢，可直接用 |
| **立创EDA 开源 PCB 的先例**（baiyanmo） | 说明 A1 可以照此交付 |

### 7.2 结论：基底不变

**已选定的 `snqx-lqh/Stm32BalanceCar` 仍是最优解**——它同时满足
F103C8T6 + HAL + FreeRTOS + Keil 四项硬约束，且有可编辑 PCB 与 Gerber。
本轮找到的项目**没有一个能同时满足这些**。

**本轮的价值在于**：提供了**上位机、协议、状态机、交付物组织**四方面的参照，
而这几块恰恰是我们**必须自研**的部分。

### 7.3 明确的自研范围（无参照可抄）

- **A2 结构方案 / 装配图 / 外观效果图** —— 全体项目空缺
- **任务执行状态机 + 任务进展上报** —— 仅概念级参照
- **"四角色完整闭环"的整合** —— 无现成案例
