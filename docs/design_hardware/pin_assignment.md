## 一、硬件与技术栈概况

| 项目 | 内容 |
|---|---|
| 主控 | **STM32F405RGT6**（Cortex-M4F，LQFP64，1MB Flash / 192KB RAM）<br>同一块板可换焊 STM32F103RC（**两者 pin-to-pin 兼容**） |
| 系统时钟 | 168 MHz（`delay_init(168)`） |
| 固件库 | **ST 标准外设库（FWLIB）**，非 HAL 库 |
| 工程格式 | **Keil 4 工程（`Minibalance.uvproj`）**，无 `.ioc`、无 CMake/Makefile |
| 调度方式 | **裸机超级循环（无 FreeRTOS）**；控制逻辑跑在 MPU6050 的 INT 外部中断里，10 ms 周期 |
| IMU | **MPU6050（板载集成）**，经**软件 I2C** 访问；INT 接 EXTI |
| 姿态算法 | 默认卡尔曼滤波（另有 DMP / 互补滤波版本源码） |
| 显示 | OLED，**软件 SPI**（4 线） |
| 通信 | 蓝牙 = USART2；调试/上位机 = USART1；另有 CAN、NRF24L01（源码中已注释禁用） |
| 上位机协议 | 厂商自有 **DataScope** 协议（`$` 帧头 + float 数组 + 长度尾字节） |

### 1.1 控制周期（源码实测）

`control.c` 的 `EXTI15_10_IRQHandler()` 由 MPU6050 INT 触发，内部用 `Flag_Target` 交替：

- **5 ms**：读姿态（`Get_Angle`）+ 读遥控 + 读电池电压
- **10 ms**：读编码器 + 平衡 PID + 速度 PID + 转向 PID + PWM 输出

> ⚠️ 这与旧基底（FreeRTOS + 5 ms 任务）完全不同，改造方案需相应调整。

## 三、★ 空闲资源（外挂模块的接入点）

### 3.1 空闲且支持 ADC 的引脚 —— 气体传感器必须用这些

以下 8 个引脚**源码中未被任何启用路径引用**，且具备 ADC 功能：

| 引脚 | ADC 通道 | 备注 |
|---|---|---|
| **PA4** | ADC12_IN4 | 空闲 |
| **PA5** | ADC12_IN5 | 仅出现在**已禁用**的 SPI1（NRF24L01）路径 |
| **PA6** | ADC12_IN6 | 仅出现在**已禁用**的 SPI1 路径 |
| **PA7** | ADC12_IN7 | 仅出现在**已禁用**的 SPI1 路径 |
| **PC1** | ADC123_IN11 | 空闲 |
| **PC3** | ADC123_IN13 | 空闲 |
| **PC4** | ADC12_IN14 | 仅出现在**已禁用**的 NRF24L01 路径 |
| **PC5** | ADC12_IN15 | 仅出现在**已禁用**的 NRF24L01 路径 |

> **为什么可用**：`main.c` 中 `NRF24L01_Init()` 与模块自检**均被注释掉**，SPI1 也随之不启用。
> 因此 PA5/PA6/PA7 与 NRF 的 PC4/PC5 实际处于空闲状态。

### 3.2 空闲的数字 IO

| 端口 | 空闲引脚 |
|---|---|
| GPIOA | PA4, PA5, PA6, PA7（**PA13/PA14 为 SWD，保留**） |
| GPIOB | PB2, PB3, PB12 |
| GPIOC | PC1, PC3, PC4, PC5, PC8–PC12 |
| GPIOD | PD0, PD1, PD2 |

### 3.3 原理图上的物理接口（**供参考，需实物复核**）

从主板原理图读到以下预留接口（该 PDF 为 2020 年版，与源码版本可能不一致）：

| 接口 | 丝印 | 引出信号 |
|---|---|---|
| **NRF24L01 无线模块接口** | Header 4X2 | **PC4、PA7、PB12、3V3** / **PA6、PA5、PC5、GND** |
| 超声波接口 | J2 | 5V、PB1、PB0、GND |
| 蓝牙接口 | Header 4 | 5V、PA3、PA2、GND |
| 拓展电源 | Header 4X2 | 5V / GND 多路 |
| PC6~9 | Header 4 | PC9、PC8、PC7、PC6 |
| 电机编码器接口 1 / 2 | J10 / J8 | 电机相线 + 编码器 + 5V + GND |
| SWD（STLINK/JLINK） | — | GND、IO、SCK、3V3 |
| CAN | Header 2 | CANH、CANL |
| 拓展 Arduino nano 接口 | — | 大量引脚（仅在改用 Arduino 控制时才用） |

> ⭐ **最重要的发现**：**NRF24L01 接口（2×4 排针）同时引出了 PA5、PA6、PA7、PC4、PC5 五路空闲
> ADC 引脚 + 3V3 + GND**。由于 NRF24L01 在源码中已禁用、本项目也不需要，**这个接口是两路气体
> 传感器模拟信号最理想的接入点**——插上杜邦线即可，**不需要改板**。

## 四、本项目外挂模块的引脚分配建议

| 模块 | 数量 | 信号 | 建议引脚 | 备注 |
|---|---|---|---|---|
| **MQ-2 气体传感器** | 1 | AO（模拟） | **PA5** | 经分压后接入；可选 NRF 接口第 4 脚 |
| **MQ-135 气体传感器** | 1 | AO（模拟） | **PA6** | 经分压后接入；可选 NRF 接口第 2 脚 |
| **DHT11 温湿度** | 1 | 单总线 | **PB3** 或 **PC1**（纯 GPIO） | 需 4.7k 上拉至 3.3V |
| **红外避障（左/右）** | 2 | GPIO 输入 | **PA4**、**PA7** | 或 PC3、PC8 |
| **蜂鸣器** | 1 | GPIO 输出 | **PB12** | 5V 蜂鸣器需三极管驱动 |
| 备用 | — | 模拟/数字 | **PC3、PC4、PC5、PC8–PC12** | 余量充足 |

**占用统计**：气体占用 PA5/PA6，数字占用 PB3、PA4、PA7、PB12，**仍余 PC1/PC3/PC4/PC5/PC8–PC12 等 8 个以上**。

### 4.1 供电

| 需求 | 方案 |
|---|---|
| 气体传感器加热丝 **5V / 约 300mA（两路）** | 从**拓展电源接口**或**超声波接口的 5V 脚**取电；**不可用 NRF 接口的 3V3**（电流与电压都不够） |
| 信号参考地 | 与主板共地（NRF 接口第 8 脚即为 GND） |

> **务必现场核算**：该车为 2S/3S 锂电 + 12V→5V 稳压模块。两路 MQ 加热丝约 300mA，
> 需确认 5V 稳压模块与走线的余量（见 `sensor_interface_notes.md` 的供电注意）。

### 5.1 ✅ 已确认（由实物照片与组员现场核对）

## 六、与立项文档的差异（需同步修订）

本项目任务书（已提交）中关于 B 角色的描述与本基底存在一处**实质差异**：

| 项目 | 任务书中的描述 | 本基底实际情况 | 处置 |
|---|---|---|---|
| RTOS | "Keil 开发环境搭建、**FreeRTOS 移植**" | **无 FreeRTOS**，为裸机超级循环 | **已决策**：采用**混合架构**——平衡控制保留在 MPU6050 中断中（5ms/10ms 节拍不变），新增气体采集、通信、任务状态机、界面进 FreeRTOS 任务。详见 `design_firmware/architecture.md` |
| 固件库 | 未明确 | **标准外设库**（非 HAL） | 报告技术选型需相应表述 |
| 姿态算法 | 未明确 | 默认**卡尔曼滤波**（已选定沿用） | 与用户决定一致 ✅ |
| IMU | MPU6050 | **MPU6050 板载** | 一致 ✅ |
| 上位机 | Qt C++ 自行开发 | 本基底自带 DataScope 协议与厂商上位机 | 可参考其协议，但 C 仍自研（维持原决定） |
