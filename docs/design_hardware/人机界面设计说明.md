## 1. 概述

### 1.1 人机界面的三个通道

现场人机界面三条通道，全部由 STM32 固件独立完成，不依赖上位机：

| 通道 | 器件与位置（引脚） | 承担的职责 |
|---|---|---|
| **OLED 显示** | 0.96 寸 128×64 单色模块，**软件 SPI（4 线）**：`PC0`=DC、`PC13`=SCL、`PC14`=SDA、`PC15`=RST | 就地显示环境（双路气体浓度、Rs/R0、温湿度、报警标志）与巡检状态（阶段/任务/巡检点/通信统计） |
| **按键交互** | 板上 **USER 按键**（1 个），`PB14`（输入，上拉；丝印 `USERKEY-B14`） | 单击 = 启停；双击 = 切换 OLED 页；长按 = 普通/避障模式 |
| **声光报警** | 蜂鸣器 `PC5`（`J18`，**有源，低电平响**）；LED `PB13`（丝印 `USERLED-B13`） | 气体确认超阈值 / 进入故障阶段 → 蜂鸣器连续响；LED 指示避障模式 |

**边界**：PC 端界面（历史曲线、远程控制、数据落盘）由**角色 C** 负责，不属本文档范围；本机 OLED
是"现场界面"、C 的界面是"远程/历史界面"，两者**数据来源是同一套协议**（见 §6）。

## 2. 交互总体设计

"用户想做什么 → 怎么操作 → 得到什么反馈"：

| 我想…… | 操作 | 反馈 | 数据/实现来源 |
|---|---|---|---|
| 知道现场有没有气体异常 | 看页 1（双击切页） | 双路 ppm、`Rs/R0`、`ALM`/`A` 报警标志；蜂鸣器同时响 | `pages.c` `show_gas_page()`；`app_tasks.c` UiTask |
| 知道巡检跑到哪一步了 | 双击切到页 2 | 阶段文本、任务号、进度 %、巡检点、停车原因 | `pages.c` `show_patrol_page()` |
| 知道车为什么停着不动 | 看页 2 第 3 行的 `STOP nn` 与 `LOCK` | 停车原因位图 + 安全停车锁存标志 | `patrol.h` `PATROL_STOP_*`；`app_api.h` |
| 排查"上位机连不上" | 看页 2 第 4~6 行 | 两条链路各自的收字节数、有线丢弃数、`FR` 解帧数、`Hp` 剩余堆 | `app_api.h` `AppDiag` |
| 启停小车 | USER 按键**单击** | 电机使能状态翻转（`Flag_Stop`）；**安全停车锁存期间该操作无效** | `control.c` `Key()` |
| 切换显示页 | USER 按键**双击** | 页序 0 → 1 → 2 → 0 循环，右上角页码随之变化 | `pages.h` `Pages_Next()`；`pages.c` |
| 切普通/避障模式 | USER 按键**长按** | `Bi_zhang` 翻转（0 普通 ↔ 1 避障）；页 0 模式文本变化，LED 常亮 | `control.c` `Key()`；`led.c` `Led_Flash()` |
| 看历史曲线、远程下发任务 | 交上位机（角色 C），本机做不到 | 见 §6 | `../protocol/communication_protocol.md` |

**刷新节奏**（`app_config.h`）：UI 任务周期 `CFG_UI_TICK_MS = 100` ms（OLED 每 100 ms 重绘一次）；
气体每 `CFG_GAS_POLL_MS = 50` ms 采样，巡检状态每 `CFG_STATE_TICK_MS = 100` ms 推进
—— 页面上看到的数值最多滞后约 100 ms。

## 3. OLED 显示设计

### 3.1 硬件与绘制约定

| 项目 | 值 | 依据 |

| 项目 | 设计 |

### 3.6 排布约束与核算结论

1. **两条步距不一样**（照 `oled.c` 源码）：`OLED_ShowString()` 每字符 **8 px**（函数内 `x += 8`，`MAX_CHAR_POSX = 122`）→
   一行最多 **16 个字符**（0, 8, 16 … 120）；`OLED_ShowNumber(...,12)` 每个数字 **size/2 = 6 px**，前导零显示为空格。
   "每行 21 字符"（128 ÷ 6）只在"用满 128 像素"的意义上成立，**数字字段**能这么密，字符串字段不能。
2. **★ 2026-10-09 复核后已修正**：本次核对称发现 `pages.c` 的 `show_x1()`/`show_x2()` 把 `.` 与小数位**按"每字符 6 px"排**（`.` 压到数字上）、页 2 也有几处压字；现已改掉并同步到本文档。修正后的口径：整数 2 位（12 px）→ `.` 在 x+12（8 px）→ 小数从 x+20 起（每数字 6 px），即 `show_x1` 宽 **26 px**、`show_x2` 宽 **32 px**。
3. **核算结论**：逐字段相加后，页 1/页 2 **所有右边界最大 120 px（无越界）**、**无重叠** ——
   页 1 第 1 行的 `FAST` 已由 x=90 调至 **x=88**（88~119），与页码（x=120）不再相交（见 §3.3 提示）；
   其余均已排开：页 2 第 2 行 `PROG`(52..83) 与进度(84..101) 相邻、第 3 行原因值(64..75) 与 `LOCK`(88..119) 留 13 px 空档。
4. **不越界的前提**：各数字字段的**位数固定**（任务号 2 位、进度 3 位、字节数 5 位、剩余堆 4 位、丢弃 3 位、巡检点 1 位）
   —— 数值超过位数时 `OLED_ShowNumber` 只显示**低位**（丢弃高位），不会写出屏幕；若以后要显示更大的数，需 B 侧加位数。
5. **页 0（厂商页）未动**，其排布仍按厂商原始坐标（`show.c`），本文档 §3.2 只是记录现状。

## 4. 按键交互设计

### 4.1 语义表

| 操作 | 语义（RTOS 模式） | 反馈 | 实现位置 |
|---|---|---|---|
| **单击** | 启停（`Flag_Stop` 翻转），**厂商原语义** | 电机使能/关闭；页 2 的 `LOCK` 与 `STOP` 反映相关状态 | `control.c` `Key()`：`if(tmp==1 && App_MotorDisable==0) Flag_Stop=!Flag_Stop;` |
| **单击（安全锁存期间）** | **无效** —— 禁止用按键绕过安全停车锁存 | 无任何变化 | 同上，条件里的 `App_MotorDisable==0`（决策 47） |
| **双击** | **切换 OLED 显示页**（页 0/1/2 循环） | 整屏换页 + 右上角页码变化 | `control.c`：`if(tmp==2) Pages_Next();` |
| **长按** | 普通 ↔ 避障模式（`Bi_zhang` 翻转），**厂商原语义不变** | 页 0 的模式文本变化；LED 变为常亮 | `control.c`：`if(tmp2==1) Bi_zhang=!Bi_zhang;` |

> 裸机（`USE_RTOS=0`）对照：双击是切 `Flag_Show`、单击无安全锁存判断，长按相同（页 1/2 只在 RTOS 模式下编译）。

### 4.2 与安全策略、扫描实现的关系

- **安全停车是锁存的**：500 ms 失联 / 急停（0x2F）/ 硬件故障 / 任务超时都会置位锁存（`Patrol_MotorsDisabled()` → `App_MotorDisable`），
  控制中断每拍据此**强制** `Flag_Stop = 1`；**解除锁存的唯一人工路径是上位机重新下发任务或显式使能，不是按键**（决策 47）。
- 长按与双击在锁存期间**仍有效**（不改电机使能，只改显示/运动模式，属"查看/配置"类操作）；`Key()` 由 `EXTI15_10_IRQHandler()`
  在**每条控制拍**里调用，中断内不调 FreeRTOS API、不碰 OLED（只改变量），符合中断安全约束。
- **操作手感提示（给结构/演示）**：单击约 0.25 s 后才被确认 → **双击必须"快按两下"**；长按需**持续按住**（约 200 次扫描），松手过早会判成单击。

### 4.3 判定方式与阈值（`key.c`）

| 手势 | 判定方式 | 阈值（代码中的原始值） |
|---|---|---|
| 单击 | `click_N_Double(time)`：检测按下沿（`double_key`），松开后累计 `count_single`；超过 `time` 且期间未长按 → 返回 1 | 调用处 `time = 50`（扫描次数）→ 约 **0.25 s** 后确认单击 |
| 双击 | 同函数：检测到**第 2 次按下沿**立即返回 2（`double_key == 2`） | 两次按下沿的间隔必须小于上面的单击确认窗 |
| 长按 | `Long_Press()`：按住期间 `Long_Press_count` 累加；`> 200` 返回 1 | **200 次扫描**（连续按住，百 ms 量级）；长按期间单击计数被清掉（`Forever_count > time`），不会误判成单击 |
| 消抖 | 以"扫描周期判定"代替软件延时：同一按下沿只计一次（`flag_key`），松开（`KEY == 1`）才复位 | 无额外 RC / 延时消抖 |

## 5. 声光报警设计

### 5.1 蜂鸣器

| 项目 | 值 |
|---|---|
| 位置与类型 | 板上 `J18`（3 针 `+5V / PC5 / GND`），**PC5 直连**（不用三极管 `Q1`）；**有源**模块（自带振荡，**不需要 PWM**），5 V |
| 极性 | **低电平响**：`Buzzer_On()` → `PC5 = 0`；`Buzzer_Off()` → `PC5 = 1`；上电即置高，避免上电乱叫 |
| 驱动节拍 | UI 任务每 `CFG_UI_TICK_MS = 100` ms 判断一次并设置 GPIO |

**响的条件**（`app_tasks.c` UiTask，与源码逐字对应）：`beepOn = (s_mq2.alarm || s_mq135.alarm || s_patrol.phase == PROTO_PHASE_FAULT); Buzzer_Set(beepOn);`

即 **① MQ-2 确认超阈值，或 ② MQ-135 确认超阈值，或 ③ 状态机进入 `FAULT` 阶段** → 蜂鸣器**连续响**，否则停。
实现上是"电平跟随"，**没有软件间歇/变频鸣叫**（不是"滴滴"声，而是持续声）。

### 5.2 LED

| 项目 | 值 |
|---|---|
| 位置 | 板载 LED，`PB13`（**低电平点亮**：初始化时 `GPIO_SetBits(PB13)` = 灯灭） |
| 语义（普通模式 `Bi_zhang == 0`） | `Led_Flash(100)`：每 **100 次控制中断调用**翻转一次（源码注释表述为"1 s 改变一次状态"），做"程序在跑"的指示 |
| 语义（避障模式 `Bi_zhang == 1`） | `Led_Flash(0)`：`LED = 0` **常亮**，提示当前处于避障模式 |
| 故障指示（RTOS 钩子） | 任务栈溢出 / 堆耗尽时 **LED 常亮 + 关中断停住**，便于调试器定位（见 `../design_firmware/程序说明文档.md` §7 第 10 条） |

### 5.3 报警的现场含义（给装配/演示用）

| 现象 | 含义 / 现场处置 |
|---|---|
| 蜂鸣器连续响 + 页 1 出现 `ALM`/`A` | 气体确认超阈值（默认 MQ-2 30.0 ppm / MQ-135 50.0 ppm）→ 看 `Rs/R0` 趋势判断是尖峰还是持续上升 |
| 蜂鸣器连续响 + 页 2 阶段 `FAULT` | 状态机故障（硬件故障/任务超时等）→ 看 `STOP nn` 定位、看 `LOCK` 确认已锁存 |
| 蜂鸣器不响但有 `LOCK`；或 LED 常亮 | 锁存未进 `FAULT`（如 500 ms 失联）→ 查 `BT rx`/`WR rx` 是否还在增长；LED 常亮 = 避障模式（长按切回） |

## 6. 与上位机界面的分工

| 维度 | 本机 OLED（本文档，A2/B 侧现场界面） | 上位机 PC 界面（角色 C） |
|---|---|---|
| 屏幕 | 0.96 寸 128×64 单色，6 行 × 21 字符 | PC 显示器，图形化 |
| 内容 | 当前时刻的**实时值**：双路 ppm、`Rs/R0`、温湿度、阶段/任务/巡检点/链路统计 | **历史曲线、多通道趋势、日志与回放**、远程控制面板、参数设置 |
| 操作 | 1 个按键（单击/双击/长按） | 鼠标键盘：任务下发、使能、急停、在线调参 |
| 数据通道 | 无（本地显示，数据来自 `app_api.h` 只读接口） | 蓝牙 SPP（USART2，115200）/ 有线（USART1，115200），**同一套协议帧**（协议见 `../protocol/communication_protocol.md`） |

要点：OLED 上每个量都能在协议上行帧里找到对应字段（角度/浓度/状态/诊断），不会"口径不同"（接口约定见 `../design_firmware/程序说明文档.md` §5.5）；页 1/2 数据全部走 `app_api.h` 只读快照接口（`App_GetGas/GetPatrol/GetDiag`），**显示与业务解耦**；上位机侧的界面设计与操作手册由 C 负责，**不在本文档内**。
