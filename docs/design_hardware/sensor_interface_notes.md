## 一、气体传感器接入的三个硬约束

### 1.1 模拟输出必须分压（否则烧 MCU）

MQ 系列模块在 **5V 供电**下，模拟输出（AO）最高可接近 5V；而 STM32 的 ADC 输入上限是 **3.3V**。
直连会永久损坏 MCU 引脚。

**结论**：每一路 MQ 的 AO 都必须经电阻分压后再接 ADC。

分压网络选型（5V 输入，目标 ≤3.3V）：

| R 上 / R 下 | 分压比 | 5V 对应输出 | 评价 |
|---|---|---|---|
| 10kΩ / 20kΩ | 0.667 | 3.33V | 边缘，略超 3.3V |
| **10kΩ / 15kΩ** | **0.600** | **3.00V** | **推荐，留有余量** |
| 10kΩ / 10kΩ | 0.500 | 2.50V | 安全但牺牲分辨率 |

> 分压电阻尽量靠近 MCU 端放置；信号线就近加 0.1µF 去耦。

### 1.2 加热丝必须独立供电，且要能扛住电流

- 单路 MQ 加热丝约 **150 mA @5V**，两路合计约 **300 mA**，五路则达 **750 mA**。
- 加热丝是**脉冲负载**，会在电源线上引入纹波，污染 ADC 读数与 IMU 稳定性。

**结论**：
- 供电走线加宽（每路 300mA 建议 ≥40mil）；
- 每个模块的 VCC–GND 就近加 **100µF 电解 + 0.1µF 陶瓷**；
- 加热丝供电线**不要与 I2C、编码器信号线并行**；
- 若路数超过 3 路，必须核算板载 5V 走线容量（1oz 铜、0.5mm 宽约 0.9–1.2A），必要时独立降压。

### 1.3 预热是强制的，且要 24–48 小时

MQ 系列首次通电读数会持续漂移，**必须连续老化 24–48 小时**才能稳定标定。

**结论**：模块领到后**立即通电老化**，不要把这段等待期留在关键路径上。
老化期间正好并行开发上位机与协议，不浪费时间。

## 二、通信与总线：三个会踩的坑

### 2.1 I2C 多设备共用必须加互斥锁

OLED 与 IMU 常挂在**同一条 I2C** 上。若在多任务环境下不加保护，两个任务交错访问总线会导致
**挂起或数据错乱**（参考实现中就因此加了互斥量）。

**结论**：任何共用 I2C 的访问点，都要用 RTOS 互斥量串行化。
本项目若再加 DHT11（单总线，不占 I2C）或其它 I2C 器件，同样要纳入保护。

### 2.2 硬件 I2C 可能因引脚复用而失效，软件 I2C 是备用方案

参考实现中曾出现 **I2C 与 SPI 重映射引脚冲突导致死机**，最终改用**软件 I2C** 绕开。

**结论**：规划引脚时优先避开复用冲突；固件里为 I2C 预留"可切换软件实现"的抽象层。

### 2.3 串口是稀缺资源，会打架

蜂鸣器、WiFi、蓝牙、调试口都想用串口/DMA。参考实现中**蜂鸣器与 WiFi 抢串口导致 DMA 冲突，
只能发送一次**且未解决。

**结论**：**先规划串口分配，再分配引脚**。本项目若以蓝牙为主链路，WiFi 串口可释放留作备用。

## 三、上位机（与基底无关）

- 通信层与协议层**必须解耦**：协议编解码做成纯逻辑模块，不依赖任何 GUI，才能独立单元测试。
- 实时曲线用**环形缓冲 + 定时刷新（10–20 fps）**，不要每次收包都重绘，否则界面会卡死。
- 数据落盘按**价值分层**：常态降采样留痕，异常区间全量留痕，兼顾完整性与体积。

## 四、PID 调试（与基底无关）

平衡控制的难点不在算法，而在**迭代速度**：

1. **在线调参通道**是前提——参数能不发重编译就生效，并支持**回读确认**；
2. **高速遥测流**——调参模式不下发常规协议，而以 100–200 Hz 连续吐原始浮点数组供波形观测；
3. **安全保护必须有**——角度超限切电机、PWM 限幅、积分限幅、输出斜坡上升，否则每次失败都撞硬件；
4. **分环整定**——直立环 → 速度环 → 转向环，一次只调一个；
5. **做一个调试架**——能约束车身只能单自由度摆动，让每次试验可重复、硬件风险归零。
   这是投入产出比最高的一项，比任何软件工具都重要。
