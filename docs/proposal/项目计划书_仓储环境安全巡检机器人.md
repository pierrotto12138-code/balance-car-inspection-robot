## 3. 主要功能

### 3.1 机器人特定任务

**任务名称**：仓储环境安全巡检

**任务流程**：

1. **上电自检**：对传感器、电机驱动、通信链路进行自检，结果上报监控系统；
2. **传感器预热**：气体传感器通电预热（3–5 分钟），OLED 就地显示倒计时，预热完成后向上位机上报「就绪」事件；
3. **等待启动**：进入待机状态，等待上位机下发启动指令；
4. **自主巡航**：沿预设巡检点路径自主行进，采用红外传感器沿边循迹、超声波测距避障，遇障自动避让并回传环境信息；
5. **沿途采集**：以 **1 Hz** 常态频率采集双路气体浓度与环境温湿度，同时采集姿态、轮速与当前位置，周期性上报；
6. **边缘研判**：任一气体通道连续 3 帧超出阈值即判定异常，触发以下动作：
   - 蜂鸣器声光报警，OLED 就地显示异常通道与浓度；
   - 向上位机上报「气体超阈值」告警事件；
   - **自适应升频**至 5 Hz 加密采样，并就地驻留；
7. **巡检完成**：走完全部巡检点后，上报巡检覆盖率与异常点清单，随后返回起点；
8. **全程可干预**：任何阶段均可接受上位机的运动控制、任务切换与紧急停机指令。

**完成判断标准**：巡检覆盖率 ≥ 90%（按巡检点计）；对预置可控气源的异常检出率 100%；返航后上位机生成完整巡检记录。

### 3.2 状态信息上传

| 数据类别 | 具体内容 | 上行方式 |
|---|---|---|
| 姿态参数 | 俯仰角、横滚角、偏航角、三轴角速度 | 周期上行，50 ms（20 Hz） |
| 运动状态 | 左/右轮线速度、PWM 占空比、超声波距离、避障状态位 | 周期上行 |
| **气体浓度** | **MQ-2 与 MQ-135 双通道：原始 ADC 值 + 温湿度补偿后浓度真值 + 传感器就绪状态位 + 当前采样档位** | 常态 1 Hz；异常时自适应升至 5 Hz |
| 环境参数 | 环境温度、相对湿度（DHT11） | 周期上行，1 Hz |
| 任务进展 | 任务 ID、阶段枚举、完成度百分比、当前巡检点编号 | 状态变化时 + 周期上行 |
| 位置信息 | 里程计坐标 x/y、偏航角、累计里程 | 周期上行 |
| 事件告警 | 上电自检完成、预热中、任务开始、气体超阈值、碰撞/跌落/低电压、任务完成/失败 | 事件触发时立即上报 |
| 心跳 | 链路保活帧 | 200 ms 周期 |

### 3.3 远程指令控制

| 指令类别 | 具体指令 | 执行方式 |
|---|---|---|
| 运动控制 | 线速度、角速度、使能标志 | 机器人进入遥控模式，按指令运动并回传状态 |
| 任务指示 | 任务 ID 与参数（启动巡检 / 返航 / 待机） | 机器人切换至对应任务状态机分支并回传确认 |
| 控制模式 | 平衡模式 / 遥控模式 / 自主模式切换 | 切换后回传当前模式 |
| **巡检参数** | **采样周期、双路告警阈值、自适应采样使能、温湿度补偿使能** | 参数写入并回传确认 |
| 紧急停机 | 无参数，一键停车 | 立即切断电机输出并回传确认 |

| 功能模块 | 说明 |
|---|---|
| 通信接口 | 串口（经典蓝牙 SPP 虚拟串口）双向收发，自动重连，链路状态与丢帧率指示 |
| 状态监测面板 | 姿态实时曲线（三通道）、双路气体浓度实时曲线、环境温湿度数值、任务进度条、巡检点编号 |
| 远程控制面板 | 运动控制（方向/速度）、任务启动与切换、巡检参数设置（采样周期/双路阈值/自适应使能）、一键紧急停机 |
| 告警提示 | 超阈值醒目告警、事件日志滚动显示、蜂鸣提示 |

### 3.5 其他创新功能

1. **异常驱动的自适应采样调度**：常态 1 Hz 低频巡检维持低功耗与低带宽占用，触发异常后自动升至 5 Hz 加密采样并定点驻留，以最小的能量与带宽代价换取最高信息密度；
2. **温湿度在线补偿**：以 DHT11 实测环境温湿度对 MQ 系列气体传感器的读数进行在线修正，抑制其固有的温湿度漂移；
3. **双通道交叉验证**：MQ-2（可燃气体/烟雾）与 MQ-135（空气质量/有害气体）响应谱互补，两者同时异常方触发高等级告警，单一通道异常仅作提示，显著降低误报率；
4. **多层确认机制**：连续 N 帧超阈值方判定异常，并引入差分阈值抑制环境本底缓慢漂移造成的误触发。

### 4.3 技术选型

**（1）通信方式比选**（任务书要求）

| 方案 | 有效带宽 | 通信距离 | PC 端实现复杂度 | 结论 |
|---|---|---|---|---|
| **经典蓝牙 SPP**（HC-05 / HC-06） | ~100 KB/s @115200 bps | ~10 m | **极低**：模块被系统枚举为虚拟串口，上位机用 Qt SerialPort 直接读写，无需协议栈开发 | **✅ 首选** |
| BLE 4.0 | 低（MTU 23–247 B） | ~10 m | 高：需自定义 GATT 服务，上位机需 Qt Bluetooth，Windows 端支持不佳；20 Hz 上报易拥塞 | ❌ 不选 |
| WiFi（ESP8266 / ESP32） | 数 Mbps | 30–50 m | 中：上位机用 QTcpSocket，但需现场 AP 配置，调试期增加变量 | 🔶 备选 |
| Zigbee | 250 kbps | 10–100 m | 中高：仍需协调器转串口，三周项目收益不足 | ❌ 不选 |

**选型结论**：主链路采用**经典蓝牙 SPP**，兼顾实现简单、PC 端零协议栈开发、与调试链路统一。固件侧将通信层抽象为统一接口，预留 TCP 实现，后期可在不改动上层逻辑的前提下切换。应用层自定义帧格式（见 5.5 节）。

### 4.4 经济评价（呼应新质生产力"高效能"特征）

| 维度 | 分析 |
|---|---|
| **资源占用** | 采用"异常驱动自适应采样"而非恒定高频采集：常态 1 Hz 相比恒定 5 Hz，无线带宽与上位机存储占用降低约 **80%**；上位机按数据价值分层存储（常态降采样留痕、告警区间全量留痕），在保证记录完整的前提下压缩存储需求。 |
| **功耗** | 气体传感器加热丝为最大耗电项。通过仅在采样窗口给加热丝通电、并利用其"热惯性可维持数秒读数"的特性，可进一步降低平均功耗；配合低功耗待机策略，整机续航目标 ≥ 60 min。 |
| **成本** | 主板基于已通过打样验证的开源方案改版，省去从零设计的验证成本与试错次数；传感器转接板为无源板，面积小、层数低、元件少，单板打样成本与焊接难度均很低。核心物料（MQ 系列、DHT11、OLED、超声波、红外）均可由实验室提供，主要自费项为 PCB 打样与少量接插件。 |
| **人力效率** | 复用成熟的平衡控制算法与已验证的主板设计，将有限的三人周精力集中在气体感知、补偿算法、数据闭环与系统联调等真正体现设计能力的环节，显著降低返工风险。 |

### 4.5 环境与风险分析

**能耗与环境影响**：

- 机器人以锂电池供电，相较燃油动力巡检设备无直接碳排放；
- 通过自适应采样策略降低整机平均功耗，延长单次充电作业时长，减少充电频次；
- 检测数据全流程电子化记录，替代人工持表巡检，实现无纸化作业；
- **潜在负面因素**：废旧锂电池与传感器的规范回收处置需在报告中说明。

**风险识别与应对措施**：

| 风险项 | 影响 | 应对措施 |
|---|---|---|
| MQ 传感器需 24–48 h 通电老化，否则读数漂移 | 标定数据不可用，影响验收 | **模块到货后立即通电老化**，这是模块申请需优先提交的首要原因；老化期间并行开展上位机与协议开发，不占用关键路径 |
| 环境温湿度变化导致 MQ 读数漂移、误报 | 虚假告警，可信度下降 | DHT11 温湿度在线补偿；连续 N 帧确认 + 差分阈值判定 + 双通道交叉验证，三重机制抑制误报 |
| 加装传感器后重心变化，平衡参数失配 | 平衡失稳、无法巡航 | A2 将传感器低位布置并配重下移；B 在装配完成后重新整定 PID 参数；第 1 周即完成基础平衡站立，为复调留出余量 |
| PID 整定耗时超出预期 | 挤占联调时间 | 采用成熟的直立环 + 速度环 + 转向环串级结构，参数自较小的初值逐步逼近；用 VOFA+ 实时观测波形代替盲调 |
| 演示气源浓度不可控 | 演示效果不稳定 | 使用酒精棉球作为可控气源（安全、易得、响应明显）；提前标定"浓度—距离"曲线并反复演练；准备多级浓度样本 |
| 实验室主板型号与方案不符 | 固件与引脚分配返工 | **开工前先到实验室核对主控型号、IMU 型号、无线模块与电机驱动**；固件将 IMU 与通信层抽象为接口，更换型号仅需替换驱动实现 |
| 无线链路丢包或中断 | 状态丢失、指令不达 | 帧头 + 长度 + CRC-16 校验；序列号检测丢帧；200 ms 心跳保活与自动重连；失联时机器人执行安全停车 |
| 三周工期紧张 | 功能裁剪 | 采用分阶段交付与 P0/P1/P2 功能分级（见第 7 节），确保硬性要求优先完成；创新功能定位为可降级项 |

**子系统划分与关系**：

- **感知层 → 应用层**：传感器数据经滤波与补偿后送入边缘研判模块；
- **应用层 → 控制层**：任务状态机输出期望速度与转向，控制层解算为电机 PWM；
- **应用层 ↔ 通信层**：状态数据打包上行，指令解包后驱动状态机迁移；
- **通信层 ↔ PC 端**：单一无线链路承载全部双向数据流，构成"数据上行—指令下行"的完整闭环。

### 5.2 硬件方案（A1 + A2）

**（1）电路方案（A1）**

采用**「改版主板 + 无源传感器转接板」两块板**的架构：

| 板卡 | 内容 | 设计要点 |
|---|---|---|
| **主板** | 基于已验证的平衡车开源方案改版。保留其成熟部分：STM32F103C8T6 核心板座（标准 2×20 座）、TB6612 电机驱动模块座、MPU6050 模块座、OLED 座、蓝牙模块座、超声波座、降压模块座 | ①功能模块一律采用**插座**而非芯片焊接，便于更换与调试；②**增加传感器接口排针**——将主板已引出但未使用的空闲 ADC 与数字 IO 汇总为标准 2.54 排针，供转接板接入；③**裁去本项目不用的功能座**（NRF24L01、ESP-01、舵机座），腾出引脚并简化 BOM；④保留串口下载与调试接口 |
| **传感器转接板** | **纯无源板**：排针排母、走线、双路分压电阻、去耦电容 | ①双路气体传感器各自配分压网络（气体模块 5V 供电时模拟输出可接近 5V，需分压至 STM32 的 3.3V 量程内）+ 去耦电容；②DHT11、超声波、红外避障、蜂鸣器的接口座；③与主板用 2.54 排线连接，便于分头调试；④板上**无芯片、无独立电源、无外置 ADC** |

**为什么不需要独立电源支路**：本项目仅使用 2 路气体传感器，加热丝总电流约 300 mA @5V。主板板载 5V 走线容量约 0.9–1.2 A，现有负载（核心板、编码器、OLED、蓝牙）约 100 mA，**总负载约为走线容量的 40% 以下，余量充足**，无需额外增加降压模块与扩流走线——这是本方案相较"多通道阵列方案"在工作量与风险上的关键简化。

**电源架构**：

```
锂电池
   ├─→ 电机驱动（TB6612，直供）
   ├─→ 主板降压模块 → 5V ─┬→ 核心板 / OLED / 蓝牙 / 超声波 / 编码器
   │                      └→ 转接板 → 双路气体传感器（分压后 → ADC）
   └─→ 主板 3.3V（核心板 LDO）→ 转接板 → DHT11 / 红外避障 / 蜂鸣器驱动
```

**关键设计约束**：气体模块的模拟输出（AO）在 5V 供电下最高可接近 5V，**必须经分压网络（如 10 kΩ / 20 kΩ）降至 3.3V 以内**再接入 MCU 的 ADC 引脚，否则会损坏 MCU。

**（2）结构方案（A2）**

| 项目 | 方案 |
|---|---|
| 总体布局 | 主板与转接板分层堆叠（铜柱支撑），电池置于底盘低位，传感器与转接板靠近底盘安装 |
| 布局依据 | 传感器低位布置可降低整车重心，改善平衡稳定性；同时避开电机与轮组，减少气流扰动与振动干扰 |
| 外观设计 | 外壳采用 3D 打印件，顶部预留 OLED 视窗与按键开孔，侧面开设传感器进气格栅与散热孔 |
| 人机界面 | OLED 显示巡检状态与实时浓度；按键用于模式切换与紧急停机；蜂鸣器 + LED 声光报警 |
| 装配要求 | 转接板安装孔位与主板外形匹配；线束走向避开轮组与传感器进气口 |

**（3）物料清单（BOM）要点**

主要物料：STM32F103C8T6 核心板、TB6612FNG 电机驱动模块、MPU6050 模块、MQ-2 模块、MQ-135 模块、DHT11 模块、0.96" OLED 显示屏、HC-SR04 超声波模块、红外避障模块 ×2、5V 蜂鸣器模块、降压模块、锂电池与充电器、车架底盘套件、排针排母与杜邦线、分压电阻与电容、结构件。详细 BOM 将在设计阶段完成后单独提交。

### 5.3 软件方案（B）

**（1）FreeRTOS 任务划分**

| 任务 | 优先级 | 周期/触发 | 职责 |
|---|---|---|---|
| **控制任务** | 最高 | 5 ms（200 Hz） | PID 平衡控制（直立环 + 速度环 + 转向环）、电机 PWM 输出 |
| **IMU 采集任务** | 高 | 5 ms（200 Hz） | MPU6050 姿态读取、滤波、姿态解算 |
| **传感器采集任务** | 中 | 1000 ms（常态）/ 200 ms（异常） | 双路气体 ADC 采集、DHT11 温湿度读取、补偿计算 |
| **任务执行状态机** | 中 | 100 ms | 任务阶段迁移、边缘研判、巡检点管理、避障决策 |
| **通信任务** | 中 | 20 ms（上行）+ 200 ms（心跳） | 状态数据打包上行、指令解包与分发、心跳发送 |
| **人机交互任务** | 低 | 100 ms | OLED 刷新、按键扫描、蜂鸣器报警 |

任务间通过**消息队列**传递数据；I2C 总线等共享资源用**互斥量**保护，避免 MPU6050 与 OLED 的访问冲突。

**（2）传感器采集方案**

- **姿态**：MPU6050 经 I2C 采集三轴加速度与角速度，采用互补滤波融合（或使用其内置 DMP 硬件解算），输出欧拉角；
- **气体**：MQ-2 与 MQ-135 的模拟输出经分压后接入 MCU 的 ADC 引脚，由 DMA 多通道循环采样；
- **温湿度**：DHT11 单总线数字输出；
- **测速**：编码器正交解码，四倍频计数得到轮速与里程；
- **测距**：HC-SR04 由定时器输入捕获测距；红外避障模块由 GPIO 电平检测。

**（3）补偿与研判算法**

```
步骤 1：原始值采样    —— ADC 读取双路气体原始值，滑动平均滤波
步骤 2：温湿度补偿    —— 依据 DHT11 实测温湿度，按经验系数修正读数
步骤 3：基线归一化    —— 以预热完成后的洁净空气读数作为基线 R0，计算 Rs/R0 比值
步骤 4：多层确认      —— 连续 3 帧超阈值方判定异常（抑制单帧抖动）
步骤 5：交叉验证      —— MQ-2 与 MQ-135 同时异常 → 高等级告警；
                        仅单通道异常 → 低等级提示（降低误报）
```

**（4）任务执行状态机**

```
        上电自检
            ↓
        [初始化] ──失败──→ [故障上报]
            ↓ 成功
        [预热中]  (3–5 min，OLED 倒计时，上报进度)
            ↓ 预热完成
        [待机] ←──────────────┐
            ↓ 收到启动指令      │
        [自主巡航] ──异常──→ [异常研判] ──确认──→ [驻留加密采样]
            ↓ 巡检点走完                            │
        [返航] ←────────────────────────────────────┘
            ↓ 到达起点
        [完成]  (上报覆盖率与异常点清单)
```

任一阶段收到紧急停机指令，立即进入 [安全停车] 状态并回传确认；链路中断超过 500 ms 亦自动进入安全停车。

**（5）通信协议方案**

详见 5.5 节。协议文档将在 B/C 双方确认后冻结为独立版本文件并提交。

**（2）界面设计**

| 面板 | 内容 |
|---|---|
| **状态监测面板** | 姿态实时曲线（俯仰/横滚/偏航三通道）、轮速显示、超声波距离、任务进度条、链路状态与丢帧率指示 |
| **气体与环境面板** | 双路浓度实时曲线（可勾选显示）、当前浓度数值、阈值参考线、超限高亮告警、环境温湿度显示 |
| **远程控制面板** | 运动控制（方向/速度）、任务启动与切换、巡检参数设置（采样周期/双路阈值/自适应使能/补偿开关）、一键紧急停机 |

**（3）数据处理方案**

- **实时显示**：内存环形缓冲 + 定时刷新（10–20 fps），避免高频重绘导致界面卡顿；
- **落盘策略**：常态数据降采样留痕（如 1 Hz 存一次），**告警区间全量留痕**（5 Hz 全存），兼顾记录完整性与存储效率；
- **存储格式**：SQLite 单库多表（状态表 / 浓度表 / 事件表 / 巡检点表），便于按时间检索；
- **回放功能**：按时间轴回放历史数据，曲线同步重现，支持导出 CSV 供报告引用。

### 5.5 通信协议

**（1）物理层**：经典蓝牙 SPP，115200 bps，8 数据位，无校验位，1 停止位（8N1）。

**（2）帧格式（通用）**

| 字段 | 长度（字节） | 说明 |
|---|---|---|
| 帧头 | 2 | `0xAA 0x55`（双字节帧头，抗干扰能力强于单字节） |
| 命令字 | 1 | 标识帧类型 |
| 数据长度 | 2 | N，数据段字节数（小端序） |
| 数据段 | N | 各命令定义 |
| 校验 | 2 | **CRC-16/MODBUS**（多项式 0xA001，覆盖命令字至数据段末尾） |

**（3）上行帧定义（机器人 → 监控系统，命令字 0x10–0x1F）**

| 命令字 | 名称 | 数据段内容 |
|---|---|---|
| 0x10 | 姿态数据 | 俯仰角、横滚角、偏航角（int16，单位 0.01°）；三轴角速度（int16，单位 0.01 dps） |
| 0x11 | 运动状态 | 左/右轮线速度（int16，mm/s）；PWM 占空比（int16）；超声波距离（uint16，cm）；避障状态位掩码（uint8） |
| 0x12 | 任务状态 | 任务 ID（uint8）；阶段枚举（uint8）；完成度（uint8，%）；当前巡检点编号（uint8）；异常标志（uint8） |
| 0x13 | 事件告警 | 事件码（uint8）；时间戳（uint32，ms）；关联数据（视事件而定） |
| **0x14** | **环境与气体** | **MQ-2 原始值（uint16）；MQ-135 原始值（uint16）；MQ-2 补偿后浓度（uint16，ppm×10）；MQ-135 补偿后浓度（uint16，ppm×10）；环境温度（int16，0.1 ℃）；相对湿度（uint16，0.1 %RH）；就绪状态位（uint8）；采样档位（uint8）** |
| 0x1F | 心跳 | 无数据段（数据长度 = 0），用于链路保活 |

**（4）下行帧定义（监控系统 → 机器人，命令字 0x20–0x2F）**

| 命令字 | 名称 | 数据段内容 | 机器人响应 |
|---|---|---|---|
| 0x20 | 运动控制 | 线速度（int16，mm/s）；角速度（int16，0.1 deg/s）；使能（uint8） | 执行后回传 0x12 任务状态 |
| 0x21 | 任务指示 | 任务 ID（uint8）；参数（uint16×N） | 切换至对应任务状态机分支并回传确认 |
| 0x22 | 控制模式 | 模式枚举（uint8）：平衡 / 遥控 / 自主 | 切换后回传当前模式 |
| **0x23** | **巡检参数** | **采样周期（uint16，ms）；MQ-2 告警阈值（uint16，ppm×10）；MQ-135 告警阈值（uint16，ppm×10）；自适应采样使能（uint8）；温湿度补偿使能（uint8）** | 参数写入并回传确认 |
| 0x2F | 紧急停机 | 无数据段 | 立即切断电机输出并回传 0x12（阶段 = 安全停车） |

**（5）事件码表（0x13 数据段首字节）**

| 事件码 | 含义 |
|---|---|
| 0x01 | 上电自检完成 |
| 0x02 | 任务开始 |
| 0x03 | 任务完成 |
| 0x04 | 任务失败 / 超时 |
| 0x05 | 碰撞 / 跌落 / 低电压告警 |
| **0x06** | **气体浓度超阈值** |
| **0x07** | **传感器预热中 / 传感器失效** |

**（6）任务 ID 表**

| 任务 ID | 名称 |
|---|---|
| 0x00 | 待机 |
| 0x01 | 自主巡检 |
| 0x02 | 返航 |

**（7）通信约定**

- **字节序**：小端（Little-Endian），与 ARM 架构默认一致；
- **状态上行**：周期 50 ms（20 Hz）；
- **气体与环境数据**：常态 1 Hz，异常时自适应升至 5 Hz；
- **事件型数据**（告警、任务切换、完成）立即上报，不等待周期；
- **心跳**：200 ms 周期；监控端 200 ms 未收到任何帧即判定链路断开并触发重连；
- **数据表示**：浮点数据统一放大为定点整数传输，避免跨平台浮点表示差异。

## 6. 新质生产力体现（≥100 字）

**高科技（技术运用与创新性）**

本项目以 MQ-2 与 MQ-135 双通道气体传感器构成互补响应阵列，并以 DHT11 实测环境温湿度对传感器读数进行在线补偿，抑制 MQ 系列固有的温湿度漂移；通过"连续多帧确认 + 双通道交叉验证 + 差分阈值"的多层研判机制，在嵌入式端本地完成异常判定，使机器人从单纯的数据采集装置升级为具备就地决策能力的边缘智能感知终端。软件层面采用 FreeRTOS 多任务架构实现感知、控制、通信的并发解耦，通信协议引入双字节帧头、长度字段与 CRC-16 校验，保障了数据链路的可靠性——传感融合、边缘计算与实时操作系统的综合运用，体现了新劳动工具的技术含量跃迁。

**高效能（资源优化与效率提升）**

系统采用异常驱动的自适应采样调度：常态下以 1 Hz 低频巡检维持低功耗与低带宽占用，一旦触发异常即自动升至 5 Hz 加密采样并定点驻留，相比恒定高频采集可降低约 80% 的无线带宽与存储占用，以最小的资源代价换取最高价值的信息密度；上位机按数据价值分层存储，仅对告警区间做全量留痕。以机器人替代人工进入仓储等潜在危险环境执行巡检，把传统"定时全量抄表"的模式转变为"按需精准响应"的模式，在提升巡检效率的同时降低了人员暴露风险，体现了数据作为新型生产要素在优化资源配置中的作用。

**高质量（成果质量与绿色低碳）**

全链路数据可追溯——每条浓度记录均带时间戳、位置坐标与补偿后真值，支持历史回放与比对，为环境异常事件提供可审计的电子记录；系统具备自动重连、丢帧检测、心跳保活与失联安全停车机制，保障长期运行的可靠性。硬件上采用"模块化插座 + 双层板卡"设计，核心模块与传感器均可独立更换而无需拆焊，延长整机使用寿命、减少电子废弃物产生。整机以锂电池驱动，相较燃油动力设备无直接碳排放，配合低功耗调度策略延长单次作业时长，是绿色低碳理念在工程实践中的具体落实，也体现了"打通科技成果转化最后一公里"的实践导向。
