#### 2.1.1 ★ "模块 → 接口"对照（**常被数错**）

**板上共 14 个连接器，但只有 8 个是"模块座"** —— 另外 6 个是结构 / 电源 / 电机接口。

| 类别 | 数量 | 位号 | 用途 |
|---|---|---|---|
| **模块座 · 模拟** | 2 | `J13` `J10` | MQ-2 / MQ-135（含分压）|
| **模块座 · 数字** | 3 | `J9` `J7` `J18` | DHT11 / 蓝牙 / 蜂鸣器 |
| **模块座 · 避障** | 3 | `J5` `J11` `J14` | 超声波 / 红外L / 红外R |
| **控制板插座** | 2 | `J1` `J2` | 2×15 + 2×15 = **60 针**，STM32 控制板直接插 |
| **电机接口** | 2 | `CN1` `CN2` | 电机 A/B 的**电机线 + 编码器线** |
| **电源** | 2 | `J17` `J15` | 12V **输入**座 / 5V-GND **取电排** |

> **常见数错**：把 6 个"模块"数成 6 个座 —— 实际是 **8 个座**，因为
> **红外是 2 个座（L/R）**，外加**超声波 1 个座**
> （任务书里"**HC-SR04 与红外模块**负责避障与循迹"是明确要求的）。
>
> **"原"板有 17 个连接器**，改板**已精简**：删 `J6`/`J8`/`J12`/`J16`，
> `J3`/`J4`→`CN1`/`CN2`，新增 `J18` → **17−4−2+2+1 = 14**。

#### 2.1.2 不装排针的座（DNP，见决策 30）

| 位号 | 状态 | 原因 |
|---|---|---|
| **`J11`** 红外避障 L | **保留焊盘，不装排针** | A1 只买了 1 个红外模块，且判断**超声波避障已足够** |
| **`J14`** 红外避障 R | 同上 | 同上 |

**为什么保留而不删**：① 任务书里"**HC-SR04 与红外模块**负责避障与循迹"是明确写了的；
② **删掉容易、加回来贵** —— PCB 阶段删了，以后要用就得改原理图 + 重画 PCB + 重新打板。
**保留焊盘零成本、可逆。**

> 副作用：`PB12`（原红外L）、`PC1`（原红外R）两个 IO 因此**空闲**，可用于后续扩展。
> 同理 `J15`（取电排）也可以**先不焊**，不影响功能。

> 另外还补了去耦：`C14/C15`（`PA5`/`PA6` 对地 0.1µF）、`C16/C17`（`+5V` 对地 0.1µF）、`C18/C19`（`+5V` 对地 100µF）。

**原理**：MQ 在 5V 下 AO 最高接近 5V，STM32 ADC 上限 3.3V，**直连会击穿引脚**。
分压比 `15/(10+15)=0.6`，5V → 3.0V，留余量。

### 2.3 ★ 原理图改法的关键（最容易搞错）

**本原理图的网络靠"网名"连接**（网名挂在导线上，同名即同网）。

```
改前:  J13.4 ─────直连───── J2.15        两边都叫 PA5  → 5V 直进 MCU，会烧
改后:  J13.4 ─[MQ2_AO]─[R10]─[PA5]─ J2.15
                ↑改名            ↑不动
```

**必须：座子侧改名，控制板侧不改名。** 两侧都改 → 网断了读不到值；都不改 → 电阻被短路，烧引脚。

**操作**（3 步）：
1. 把 `J13.4` 那条线的网名 `PA5` → **`MQ2_AO`**；`J10.3` 的 `PA6` → **`MQ135_AO`**
2. 放 5 只电阻（建议放原理图左下方空白区）
3. 给每个脚画短导线并填网名（同名自动连通，**不必真连线到控制板**）

> **详细操作**见 `docs/design_hardware/焊接调试手册.md`（含 PCB 4 步 + 飞线预案 + 验证清单）

### 2.4 供电核算（够用）

| 负载 | 电流 |
|---|---|
| 两路 MQ 加热丝 | ~300 mA @5V |
| 控制板+OLED+蓝牙+超声波+编码器 | ~100 mA @5V |
| **5V 合计** | **~400 mA**（LM2596 输出 3A，余量充足） |

**结论：不需要额外降压支路。** MQ 加热丝就近加 100µF+0.1µF 去耦。

## §5 ★ EDA 操作要点与踩坑（重要，避免重复踩）

### 5.1 两种工程格式

| 格式 | 结构 | EDA 行为 |
|---|---|---|
| `.eprj2` | SQLite 单文件 | EDA 打开时**物化到 Service Worker 缓存**，改文件不生效 |
| `.eprj3` | 文件夹 + 纯文本 JSON | **EDA 直接读**；但工程打开时 EDA 会**覆写**文件 |

**`.eprj3` 记录格式**：每行 `{头部}||{载荷}|`，如
```json
{"type":"COMPONENT","ticket":2,"id":"e1"}||{...payload...}|
```
类型：`DOCHEAD / META / COMPONENT / ATTR / WIRE / NETLABEL / PORT / TEXT / OBJ`。
**空载荷 `|||` 是合法的"删除标记"**，不是错误。

### 5.2 ★ EDA 会覆写文件（改板必须在 EDA 内进行）

**实测**：工程在 EDA 中打开时，直接改磁盘上的 `.eprj3` 文件**会被 EDA 按内存状态重写**（8 秒内）。

**推论**：
| 方式 | 可行性 |
|---|---|
| 关 EDA → 脚本改 → 开 EDA | ✅ |
| EDA 开着 → 脚本改文件 | ❌ 被覆写 |
| **在 EDA 界面里改** | ✅ **推荐** |
| 通过 EDA API 改 | ✅ 可行（EDA 负责落盘） |

### 5.3 "绿字删不掉"的根因（第七轮定论）

往届板上的注释文字（`循迹模块`、`Generic connector` 等）**只存在于 EDA 的 V3 物化缓存**里：

```
缓存位置：%LOCALAPPDATA%\LCEDA-Pro\cache.x64.3\Service Worker\CacheStorage\
缓存键名：project_<sha256(工程绝对路径)>_v6
```

**`.eprj2` 文件本身是干净的**（`documents` 表里 TEXT=0）。清缓存**必须在 EDA 完全关闭时**做，否则 EDA 立刻用内存重建。
（脚本：`hardware/clear_eda_cache.py`）

### 5.4 ★ AI 自动改板：实测不可行（已放弃）

用 EDA 官方 API 试过完整自动化（改网名+加 5 只电阻+布线+铺铜），**三类硬伤**：

| # | 问题 | 证据 |
|---|---|---|
| 1 | API 创建的元件**字段不完整** | 缺 `DeviceName`/`FootprintName`（老元件都有） |
| 2 | **`pcb_Document.importChanges()` 恒返回 false** | **未改动的原工程**测试同样 false → 该 API 在文件夹格式下不可用 |
| 3 | **DRC 收敛不了** | 双面板高密度（Top 818 / Bottom 709 障碍），新元件放哪都压到既有走线；迭代 6 轮仍有 96 条间距错误 + 1 条网表错误 |

**结论：当前没有可用的自动画板方案，改板走手工。**

### 5.5 EDA API 桥接（`Base/easyeda-bridge/`）

**用途**：让 AI 能在 EDA 进程内执行 JS（读图元、导出渲染图等）。

```bash
# 启动桥（后台）
cd D:/260921Task/Base/easyeda-bridge/easyeda-api-skill
nohup node scripts/bridge-server.mjs > /tmp/eda-bridge.log 2>&1 &

# 健康检查（edaConnected 需为 true，即 EDA 已打开）
curl -s http://127.0.0.1:49620/health

# 执行 JS（代码会被包成 async function(eda){...}，要用 return 返回值）
curl -s -X POST http://127.0.0.1:49620/execute \
  -H "Content-Type: application/json" \
  -d '{"code":"var a=await eda.pcb_PrimitiveComponent.getAll(); return String((a||[]).length);"}'
```

**常用接口**：
| 目的 | API |
|---|---|
| 列出打开标签 | `eda.dmt_EditorControl.getSplitScreenTree()` |
| 打开文档 | `eda.dmt_EditorControl.openDocument(uuid)` |
| 关闭文档 | `eda.dmt_EditorControl.closeDocument(tabId)` |
| 读 PCB 元件 | `eda.pcb_PrimitiveComponent.getAll()` |
| 读原理图元件 | `eda.sch_PrimitiveComponent.getAll()` |
| 读焊盘网络 | `eda.pcb_PrimitivePad.getAll()` |
| 铺铜重建 | `eda.sys_MessageBus.publish("doCommand_ui",["RebuildAllCopperArea"])` |
| 导出渲染图 | `eda.dmt_EditorControl.getCurrentRenderedAreaImage()` → Blob→base64 |

**文件系统接口需"全离线模式"**，且被沙箱限制在 EDA 自己的 projects 目录内。

### 5.6 `.eprj3` 末行缺 `|` 会导致底层覆铜丢失

**实测**：从 `.eprj2` 导出 `.eprj3` 时，**PCB 文件最后一条记录可能漏掉结尾的 `|`**。
EDA 解析器会跳过该记录 → 若它恰好是地平面覆铜 → **底层铜箔消失**。

**判据**：文件最后一行应以 `|` 结尾。
（脚本：`hardware/fix_eprj3_terminator.py`）

### 5.7 可复用脚本（`hardware/`）

| 脚本 | 作用 |
|---|---|
| `clear_eda_cache.py` | 清 `.eprj2` 的 V3 物化缓存（EDA 关闭时用） |
| `fix_eprj3_terminator.py` | 补末行缺失的 `|`（**从 .eprj2 导出后必跑**） |
| `clean_eprj3.py` | 删注释文字/中文丝印/FONT/layer9 元数据 |
| `clean_eprj3_meta.py` | 删 DEVICE 库元数据键、`Attribute*=REF**` 占位符 |

> 全部带 `--apply` 预演/执行两档 + 自动备份。

## §8 参考：任务书要求（摘要）

**三大交付功能**：
1. 机器人完成特定任务（我们的：自主巡检 + 双路气体/温湿度采集 + 超阈值声光报警 + 定点驻留）
2. 状态/进展/信息**上传**监控系统（姿态 20 Hz、气体环境 1 Hz→异常 5 Hz、事件即时）
3. 监控系统可**下发指令**远程控制（运动控制、任务指示、参数设置、紧急停机）

**关键指标**：巡检覆盖率 ≥90%、异常检出率 100%、告警延迟 ≤200 ms、上行丢帧 ≤1%、指令响应 ≤200 ms、平衡漂移 ≤±2°、续航 ≥60 min

**新质生产力三特征**（报告必写）：
- **高科技**：双通道气体传感+温湿度在线补偿、边缘研判、FreeRTOS、CRC-16 协议
- **高效能**：异常驱动自适应采样（1 Hz→5 Hz）、数据分层存储、机器人替代人工进危险环境
- **高质量**：全链路数据可追溯、心跳保活与失联安全停车、锂电驱动绿色低碳
