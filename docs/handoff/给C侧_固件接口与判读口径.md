## 2. 两条新增上行帧

### 2.1 `0x16` 三环实况（N = 20，1 Hz）—— **调车主力，建议 P1 就接**

| 偏移 | 字段 | 类型 | 含义 | **判读口径（重要）** |
|---|---|---|---|---|
| 0 | `balancePwm` | int16 | 平衡环输出 | 随倾角正负变化；不变化 ⇒ 姿态量没更新 |
| 2 | `velocityPwm` | int16 | 速度环输出 | **恒为 0 ⇒ 速度环没在跑**（今晚的坑，见 §5 第 4 条） |
| 4 | `turnPwm` | int16 | 转向环输出 | `Turn=0` 而两轮命令相反 ⇒ **极性/差速 bug** |
| 6 | `moto1` | int16 | 左轮命令 | ★ 见下方"注意" |
| 8 | `moto2` | int16 | 右轮命令 | ★ 见下方"注意" |
| 10 | `ccrA` | uint16 | 左轮**实际写入**的 CCR | 与 `moto1` 对照：`CCR ≈ 1.17 × |Moto|` |
| 12 | `ccrB` | uint16 | 右轮实际 CCR | 同上 |
| 14 | `encLeft` | int16 | 左编码器**本拍增量** | 手推前进时左右应**同号** |
| 16 | `encRight` | int16 | 右编码器本拍增量 | 同上 |
| 18 | `statusBits` | uint8 | 状态位 | bit0 `Flag_Stop`、bit1 `App_MotorDisable`(锁存)、bit2 本拍真的调了 `Set_pwm` |
| 19 | `buildId` | uint8 | 固件版本 | `(月<<4)|日` |

**三个"一眼定位故障"的组合（界面可做成告警/提示）**：

| 组合 | 含义 | 建议界面动作 |
|---|---|---|
| `Turn = 0` 且 `moto1 ≠ moto2` | 两轮拿到**相反命令**（差速/极性 bug） | 高亮警告（本机曾因此"原地疯狂转圈"） |
| `|moto|` 很大而 `ccr = 0` | **算出来但没执行**（保护态/未使能） | 提示"保护中，未驱动"（铁律 29 的可观测化） |
| `statusBits` bit0/bit1 置位 | `Flag_Stop` / 安全锁存生效 | 显示为"已停车/已锁存"，并给**重新使能**入口 |

**★ 注意（当前实现的一个口径）**：`moto1/moto2` 是**经过"现场极性补偿"之后**的值
（本机 `MOTOR_LEFT/RIGHT_INVERT = 1/1`，故与 `balancePwm` 符号相反），而厂商语义下
`Turn=0 ⇒ moto1 == moto2` 仍成立。B 侧待办：改为**用局部变量翻向**，让 `moto` 保持厂商语义
（届时本表会更直观，请以届时的固件版本号为准）。

### 2.2 `0x15` 诊断帧（N = 16，1 Hz）

字段顺序：电压 / 当前页号 / `Flag_Show` / 姿态算法号 / 状态位 / 剩余堆 / **OLED 写计数** / 四个任务 tick。
**字段偏移以协议 §3.4 为准**（本文不重复）。

**判读口径**：

| 观察 | 含义 |
|---|---|
| **OLED 写计数不涨** | 刷屏没在跑（界面/存储异常），不是显示内容问题 |
| **某任务 tick 不涨** | 该任务卡死/饿死（任务级存活探测） |
| 电压 < 11.1 V 持续 5 拍 | 低压保护**锁存**（要 ≥ 11.6 V 才解除），见 §4 |

## 3. 下行命令：C 侧界面必须知道的语义

### 3.1 `0x24` 参数范围（★ **以已烧录代码为准的修正版**，2026-10-15 复查）

> ⚠️ **本文档先前写的"允许范围 −500~500 / 本机定稿 −80/−0.4"，与板子上的实际代码不符**，
> 已按代码修正如下。**代码是唯一真相**（用户明确："代码我烧过没问题了，未确定的以代码为准"）。

**代码实际的范围校验**（`firmware/App/Control/param_store.c:93-101` 的 `s_range[]`，
`ParamStore_SetOne()` 在 `:116-119` 越界即 `return -2`、**不改动当前生效值**）：

| ID | 参数 | **代码允许范围** | `ParamStore_InitDefaults` 默认值 | 说明 |
|---|---|---|---|---|
| 0x01 | `Balance_Kp` | 0 ~ 1500 | 300 | — |
| 0x02 | `Balance_Kd` | 0 ~ 50 | 1 | — |
| 0x03 | `Velocity_Kp` | **0 ~ 500**（★ **不接受负值**） | 80 | 见下方"定稿值被拒"说明 |
| 0x04 | `Velocity_Ki` | **0 ~ 0.82**（★ **不接受负值**） | 0.4 | 上界 = 限幅 8200 ÷ 积分限幅 10000 |
| 0x05 | `Zhongzhi` | −20 ~ 20 | 0.5 | 平衡目标角（重心补偿），单位 °，步进 0.1 |
| 0x06 | `Turn_Kp` | −500 ~ 500 | 0 | 允许负值；★ **实际生效 52**（2026-10-15 现场启用转向环，`CFG_OVR_TURN_KP` 覆盖**被接受**，见决策 78）|
| 0x07 | `Turn_Kd` | −10 ~ 10 | 0 | 允许负值；★ **实际生效 0.5**（同上）|

**★ 2026-10-16 真机回读复核（7/7 全部回显，与上表一致）**：`300 / 1 / +80 / +0.4 / 0.5 / 52 / 0.5`
——即 **Turn 的两个值已被现场定稿覆盖且生效**（Turn 允许正负 ⇒ 不存在 Velocity 那种"被校验拒绝"的问题）；
**C 侧 `--probe-readback` 的对照表已同步为这 7 个值**（`host/src/main.cpp` 的 `kFactory[]`，此前误留 `−80/−0.4/0/0`，
会在真机上打出"与定稿值不同"的误导性提示）。原始输出见 `hardware/test_records/03_probe_readback_*.txt`。

**★ 定稿值 `−80/−0.4` 目前根本没有生效**（这是复查时新发现的，见 `app_config.h:87-94` 与
`app_tasks.c:762-766`）：

```c
#define CFG_OVR_VELOCITY_KP      -80.0f    // app_config.h:90
#define CFG_OVR_VELOCITY_KI      -0.4f     // app_config.h:91
...
(void)ParamStore_SetOne(PARAM_VELOCITY_KP, CFG_OVR_VELOCITY_KP);   // app_tasks.c:765
(void)ParamStore_SetOne(PARAM_VELOCITY_KI, CFG_OVR_VELOCITY_KI);   // app_tasks.c:766
```

而 `s_range[]` 里 `Velocity_Kp` 的**下限是 `0.0f`** ⇒ `ParamStore_SetOne()` 判 `value < lo`
⇒ **返回 -2、拒绝写入**（`param_store.c:116-119`）⇒ 上电覆盖**静默无效**，
实际生效值仍是默认的 **`+80 / +0.4`**。**这与 C 侧 `--probe-readback` 真机读到的
`+80.0000 / +0.4000` 完全一致** —— 不是"Flash 旧值"，而是"**覆盖值被自己的校验拒绝**"。
（C 侧此前把它猜成"Flash 里的旧值被载入覆盖"，**该猜测错误**，以本节为准。）

**若确实需要负增益语义**（决策 71 的结论），固件侧只需把这两行的下限改成负值：

```c
{ PARAM_VELOCITY_KP, -500.0f, 500.0f },
{ PARAM_VELOCITY_KI,   -0.82f, 0.82f },
```

改完之后 `CFG_OVR_*` 才会真正生效（`SetOne` 返回 0）。**在此之前**，
C 侧的调参界面允许填负值（不挡正确值），但**下发负值必然被拒**、回读仍为正值，
界面会按"回读 ≠ 请求"标红提示 —— 这是正确行为，不是界面 bug。

**越界行为**（★ 2026-10-15 按代码更正）：固件在**越界 / NaN / 未知 ID** 时
`App_SetPidParam()` 返回非 0 ⇒ `app_tasks.c:214` 的 `else if (... == 0)` 分支**不成立** ⇒
**整帧根本不回复**（不是"回旧值"！）。所以上位机看到的不是"回读不一致"，而是**永远等不到回读** ——
界面上表现为"待回读"卡住，必须在超时后明确提示"无回读（被拒/未实现）"，而不是一直等。
另：NaN 也一律拒绝（`param_store.c:108-111`）。
（各 ID 的**代码实际范围**见上表与 `firmware/App/Control/param_store.c:93-101`。）

### 3.2 `Zhongzhi` 的语义（不是"零漂补偿"，是**平衡目标角**）

- 固件的控制目标是**让倾角收敛到 `Zhongzhi`**；
- 本机**重心偏后约 0.5°** ⇒ 定稿 `Zhongzhi = 0.5`（让车保持该前倾角，重心落到轮轴正上方）；
- 界面文案建议写 **"平衡目标角（重心补偿）"**，单位 `°`，步进 **0.1**；
- 现场判据：调大 ⇒ 更前倾；调小 ⇒ 更后倾（**实测 1.0 后漂、0.0 前倾**）。

### 3.3 `0x20` 运动指令（已实现，带安全看门狗）

- 数据段：`linMmS`(int16)、`angDpsX10`(int16)、`enable`(uint8)；
- 语义：`|linMmS| ≥ 50` 判前后、`|angDpsX10| ≥ 100`（10 dps）判左右、`enable=0` 立即停；
- ★ **500 ms 没收到新的 `0x20` ⇒ 自动停**（上位机崩溃/断链不会让车一直跑）；
- ★ **`enable=1` 只对"失联锁存"有效**：代码里它只在
  `stopLatched && stopReason == PATROL_STOP_LINKLOST` 时清锁存
  （`firmware/App/Task/patrol.c:149-159`）。**急停锁存（`0x2F`）它解不开**（只能用 `0x21`）；
- ⚠ 因此"把 `0x20 enable=1` 当保活"确实会**周期性清掉失联锁存**（≠ 解除急停保护，
  但仍等于让"拔线保护"失效）⇒ 保活**只能用 `0x1F` 心跳**（见 §3.4）。

### 3.3.1 `0x22` 控制模式（★ **当前是空实现**，2026-10-15 复查）

- 协议里 `0x22` 写的是"控制模式 N=1"，但**固件收下它什么都不做**：
  `patrol.c:172-173` 的 `case PROTO_DOWN_MODE` 只 `return 1;`（注释原文："本状态机只记日志，不改安全策略"）；
- 真正决定"常规 / 避障 / 跟随"的是**厂商变量 `Bi_zhang`**，而它**只能靠长按按键翻转**：
  `control.c:328-329`（`if(tmp2==1) Bi_zhang=!Bi_zhang;`）⇒ 长按只能得到 **0 或 1**；
- ⇒ **`Bi_zhang==2`（跟随模式）在当前固件里没有任何赋值路径，实际不可达**；
  跟随模式那一段（`control.c:207-210`，`100 < Distance < 300` 即 10~30 cm）是厂商遗留分支；
- ⇒ **上位机目前无法切换避障模式**。若需要，请 B 实现 `0x22`（建议 0=常规/1=避障/2=跟随，带范围校验，
  且变模式时给出事件码），C 侧的模式选择器已就绪（`domain/commands.h` 的 `0x22` 构造器 + 界面）。

### 3.3.2 避障阈值（`control.c:198-206`）—— 目前**不是**参数

```c
#define TARGET_VELOCITY_NORMAL   150      /* 常规档（2026-10-15 由 110 提高，Movement 55→75）*/
#define TARGET_VELOCITY_AVOID     70      /* 避障档（由 55 提高）*/
if(Bi_zhang!=0 && Flag_sudu==1) Target_Velocity=TARGET_VELOCITY_AVOID;
else                            Target_Velocity=TARGET_VELOCITY_NORMAL;
if(Bi_zhang==1 && Flag_Left!=1 && Flag_Right!=1)
{ if(Distance<500) Movement=Target_Velocity/Flag_sudu; }   /* 500 = 50 cm：触发即后退 */
```

- ★ **真正决定快慢的是 `Target_Velocity / Flag_sudu`**（`Flag_sudu` 初值 2 = 低速档；只有厂商遥控器/APP 能置 1）；
  上位机 `0x20` 里的 `linMmS` **只用来判方向（|lin| ≥ 50），量值不参与调速** —— 想调快慢改上面这个常量
  （或按 §5 第 8 条的做法做成 `0x24` 在线可调参数）；
- `Distance` 的单位是 **0.1 cm**（`show.c:99` 用 `Distance/10` 当 cm 显示）⇒ `500` = **50 cm**；
- ★ **"触发距离"与"退到多远"是同一个数**：车一直退到超声波读数 ≥ 50 cm 为止；
  **没有回差** ⇒ 在阈值附近会前进/后退来回切换；
- 该阈值**没有对应的 `0x24` 参数 ID**。若要"在上位机实时改避障距离"，做法见 §5 第 8 条。

### 3.4 `0x1F` 心跳保活（必须，且**只能用心跳**）

固件规定 **500 ms 无下行帧 ⇒ 安全停车并锁存**（**硬件按键也解不开**）。
所以上位机必须周期发合法下行帧，**但只能用 `0x1F` 心跳**：`0x20 enable=1` 与 `0x21 自主巡航`
都会**解除安全锁存** ⇒ 若拿它们当保活，等于每 200 ms 自动拆掉一次急停保护（铁律 29 的旁路、铁律 40）。

### 3.5 左右倾角 / 左右角速度（`0x10` 的 `roll` / `gy`，2026-10-15 新增）

- **背景**：本机 `Way_Angle=2`（卡尔曼，`main.c:8`），而 `Get_Angle()` 里**只有 `way==1` 才会调用
  `Read_DMP()`** ⇒ DMP 输出的 `Pitch / Roll / gyro[] / accel[]` **从不更新、恒为 0**。
  （C 侧曾按"车靠 `-Roll` 平衡 ⇒ `Pitch` 是左右倾"的推理去取 `Pitch`：方向对，但**取不到值**，
  真机实测"横滚恒 0.00"就是这个原因。）
- **现口径**：`Angle_LR = atan2(Accel_X, Accel_Z)`（加速度计 X 轴，与厂商用 Y/Z 算平衡角**正交同构**），
  角速度取**陀螺仪 Y 轴** ⇒ **与用哪种姿态算法无关**，卡尔曼/互补/DMP 下都有效。
- ⚠ **口径要如实标注**：`Angle_LR` 是**仅加速度计的静态倾角**（未做陀螺仪融合）⇒ 车体运动/振动时噪声大；
  界面文案必须写"**静态**"，不能当成融合角。
- 开关：`app_config.h` 的 `CFG_IMU_LR_SOURCE`（0=加速度计，默认 / 1=DMP `Pitch`）、
  `CFG_IMU_LR_SIGN`（±1 翻符号）—— 一行可改，不必动别处。

### 3.6 固件特性位（`0x16` 状态位 bit3）—— ★ 判断"板上是哪版固件"

- 起因：同一天有多次构建（MQ-135 角色指派 → 转向环/提速 → 左右倾角），而 `CFG_FW_BUILD_ID`
  只能表达到"日"（`0xAF` = 10-15）⇒ 现场**无法分辨板子上跑的是哪一版**，本项目为此猜过一轮
  （一度误判"没烧进去"，实为读到了烧录前的旧数据）。
- 现约定：**bit3 = 1** 表示该构建含"左右倾角上报 / 转向环启用 / 前进档 150 / MQ-135 角色指派"。
- C 侧判读：状态条固件栏显示 `固件 0xAF/10-15 · 新特性✔` 或 `· ⚠旧构建`；
  `host.exe --probe-readback` 会直接打印该位。**未置位 ⇒ 请重烧 `firmware/build/MiniBalance.hex`。**

## 4. 保护状态：界面要如实提示什么

| 保护 | 触发 | 现象 | 界面建议 |
|---|---|---|---|
| **失联锁存** | 收到过下行帧后，静默 > 500 ms | 安全停车**并锁存** | 显示"已锁存"，提供**显式重新使能**；★ 代码上 **`0x20 enable=1` 与 `0x21` 都能解除失联锁存**（`patrol.c:149-159` 只对 `PATROL_STOP_LINKLOST` 生效），**不要**用"继续"这类含糊按钮 |
| **低压锁存** | 电压 < 11.1 V 持续 5 拍（`CFG_BAT_LOW_CONFIRM=5`，且须先过"有电池"门槛 **6.00 V**：`CFG_BAT_PRESENT_MIN=600`） | 停车，**≥ 11.6 V 才自动解除**（迟滞） | 显示电压 + "低压保护中"；★ 没接电池（USB 供电，≈4.3 V）时**按无电池处理、不是低压报警** |
| **倾角保护** | `\|倾角 − Zhongzhi\| > 40°`（`control.c:375`） | 关电机（**手把车倾过去也会触发**） | 显示"倾角超限"（现场常见，不是故障） |
| **急停 `0x2F`** | 上位机发出 | 停车锁存，**只能用 `0x21` 解除**（`0x20 enable=1` 解不开 —— `patrol.c:150` 的条件限定了 `stopReason==LINKLOST`） | 急停按钮 + 明确的解除入口 |
| **`Flag_Stop`** | 未使能 / 按键停车（单击，`control.c:320`） | 轮子不转 | 显示"已停车"；★ **按键停车后上位机无法使能**（`s_keyDisabled` 会挡住"放下自动使能"，`control.c:116`）—— 需要再按一次键，界面要如实说明 |
| **被拿起** | `Pick_Up()` 为真（`control.c:111`） | 强制 `Flag_Stop=1` | 提示"车被拿起"——放回地面且满足条件才会自动启动 |
