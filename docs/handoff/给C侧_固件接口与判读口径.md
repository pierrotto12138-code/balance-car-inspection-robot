# 给 C 侧：固件接口与判读口径（2026-10-15，B 部分收工版）

> **适用固件**：`firmware/build/MiniBalance.hex`（构建号 `0xAF` = 10 月 15 日）。
> **协议**：[`communication_protocol.md`](../protocol/communication_protocol.md) v1.2 为准，本文只补充
> **"上位机该怎么理解与显示"** 的口径，以及 **B 侧今晚踩过的坑对界面的影响**。
> **背景**：见 [`真机联调问题清单.md`](../design_firmware/真机联调问题清单.md) §8。

---

## 1. 第一件事：确认"板上是哪一版固件"

`0x16` 的**偏移 19**（原保留字节）现为**固件版本**：`(月 << 4) | 日`，本版 = **`0xAF`**（10 月 15 日）。

- **建议界面直接显示**（如状态栏 `固件 0xAF / 10-15`）；
- **一读即知**版本，避免"当前现象与预期版本不符"这类**无法定位**的争议（本项目为此白耗过一整轮）。

## 2. 两条新增上行帧

### 2.1 `0x16` 三环实况（N = 20，1 Hz）—— **调车主力，建议 P1 就接**

| 偏移 | 字段 | 类型 | 含义 | **判读口径（重要）** |
|---|---|---|---|---|
| 0 | `balancePwm` | int16 | 平衡环输出 | 随倾角正负变化；不变化 ⇒ 姿态量没更新 |
| 2 | `velocityPwm` | int16 | 速度环输出 | **恒为 0 ⇒ 速度环没在跑**（今晚的坑，见 §5 第 4 条） |
| 4 | `turnPwm` | int16 | 转向环输出 | `Turn=0` 而两轮命令相反 ⇒ **极性/差速 bug** |
| 6 | `moto1` | int16 | 左轮命令 | ★ 见下方"注意" |
| 8 | `moto2` | int16 | 右轮命令 | ★ 见下方"注意" |
| 10 | `ccrA` | uint16 | 左轮**实际写入**的 CCR | 与 `moto1` 对照：`CCR ≈ 1.17 × |Moto|` |
| 12 | `ccrB` | uint16 | 右轮实际 CCR | 同上 |
| 14 | `encLeft` | int16 | 左编码器**本拍增量** | 手推前进时左右应**同号** |
| 16 | `encRight` | int16 | 右编码器本拍增量 | 同上 |
| 18 | `statusBits` | uint8 | 状态位 | bit0 `Flag_Stop`、bit1 `App_MotorDisable`(锁存)、bit2 本拍真的调了 `Set_pwm` |
| 19 | `buildId` | uint8 | 固件版本 | `(月<<4)|日` |

**三个"一眼定位故障"的组合（界面可做成告警/提示）**：

| 组合 | 含义 | 建议界面动作 |
|---|---|---|
| `Turn = 0` 且 `moto1 ≠ moto2` | 两轮拿到**相反命令**（差速/极性 bug） | 高亮警告（本机曾因此"原地疯狂转圈"） |
| `|moto|` 很大而 `ccr = 0` | **算出来但没执行**（保护态/未使能） | 提示"保护中，未驱动"（铁律 29 的可观测化） |
| `statusBits` bit0/bit1 置位 | `Flag_Stop` / 安全锁存生效 | 显示为"已停车/已锁存"，并给**重新使能**入口 |

**★ 注意（当前实现的一个口径）**：`moto1/moto2` 是**经过"现场极性补偿"之后**的值
（本机 `MOTOR_LEFT/RIGHT_INVERT = 1/1`，故与 `balancePwm` 符号相反），而厂商语义下
`Turn=0 ⇒ moto1 == moto2` 仍成立。B 侧待办：改为**用局部变量翻向**，让 `moto` 保持厂商语义
（届时本表会更直观，请以届时的固件版本号为准）。

### 2.2 `0x15` 诊断帧（N = 16，1 Hz）

字段顺序：电压 / 当前页号 / `Flag_Show` / 姿态算法号 / 状态位 / 剩余堆 / **OLED 写计数** / 四个任务 tick。
**字段偏移以协议 §3.4 为准**（本文不重复）。

**判读口径**：

| 观察 | 含义 |
|---|---|
| **OLED 写计数不涨** | 刷屏没在跑（界面/存储异常），不是显示内容问题 |
| **某任务 tick 不涨** | 该任务卡死/饿死（任务级存活探测） |
| 电压 < 11.1 V 持续 5 拍 | 低压保护**锁存**（要 ≥ 11.6 V 才解除），见 §4 |

## 3. 下行命令：C 侧界面必须知道的语义

### 3.1 `0x24` 参数范围（★ **必须允许负值**，否则会把正确值判为非法）

| ID | 参数 | 允许范围 | 说明 |
|---|---|---|---|
| 0x01 | `Balance_Kp` | 0 ~ 1500 | 本机定稿 **300** |
| 0x02 | `Balance_Kd` | 0 ~ 50 | 本机定稿 **1** |
| 0x03 | `Velocity_Kp` | **−500 ~ 500** | ★ **本机定稿 `−80`**：本机电机/编码器符号与厂商约定相反，**负增益是正确值**，不是错误 |
| 0x04 | `Velocity_Ki` | **−10 ~ 10**（固件实际校验 −0.82 ~ 0.82） | ★ 本机定稿 **`−0.4`** |
| 0x05 | `Zhongzhi` | −20 ~ 20 | 本机定稿 **0.5**（见 §3.2） |
| 0x06 | `Turn_Kp` | **−500 ~ 500** | 本机定稿 **0**（调试期不用转向环） |
| 0x07 | `Turn_Kd` | **−10 ~ 10** | 本机定稿 **0** |

**越界行为**：固件**拒绝并保持原值**（回读仍是旧值），NaN 一律拒绝 ⇒
**界面应把"回读值 ≠ 请求值"显示出来**（本项目远程写入曾被拒而工具只报"无回显"，导致误判）。

> ⚠️ **界面若做前端校验，切勿把负值判为非法**：本机的 `Velocity_Kp/Ki = −80/−0.4` 就是出厂值。

### 3.2 `Zhongzhi` 的语义（不是"零漂补偿"，是**平衡目标角**）

- 固件的控制目标是**让倾角收敛到 `Zhongzhi`**；
- 本机**重心偏后约 0.5°** ⇒ 定稿 `Zhongzhi = 0.5`（让车保持该前倾角，重心落到轮轴正上方）；
- 界面文案建议写 **"平衡目标角（重心补偿）"**，单位 `°`，步进 **0.1**；
- 现场判据：调大 ⇒ 更前倾；调小 ⇒ 更后倾（**实测 1.0 后漂、0.0 前倾**）。

### 3.3 `0x20` 运动指令（已实现，带安全看门狗）

- 数据段：`linMmS`(int16)、`angDpsX10`(int16)、`enable`(uint8)；
- 语义：`|linMmS| ≥ 50` 判前后、`|angDpsX10| ≥ 100`（10 dps）判左右、`enable=0` 立即停；
- ★ **500 ms 没收到新的 `0x20` ⇒ 自动停**（上位机崩溃/断链不会让车一直跑）；
- `enable=1` **会解除安全锁存** ⇒ 别拿它当保活（见 §3.4）。

### 3.4 `0x1F` 心跳保活（必须，且**只能用心跳**）

固件规定 **500 ms 无下行帧 ⇒ 安全停车并锁存**（**硬件按键也解不开**）。
所以上位机必须周期发合法下行帧，**但只能用 `0x1F` 心跳**：`0x20 enable=1` 与 `0x21 自主巡航`
都会**解除安全锁存** ⇒ 若拿它们当保活，等于每 200 ms 自动拆掉一次急停保护（铁律 29 的旁路、铁律 40）。

## 4. 保护状态：界面要如实提示什么

| 保护 | 触发 | 现象 | 界面建议 |
|---|---|---|---|
| **失联锁存** | 收到过下行帧后，静默 > 500 ms | 安全停车**并锁存** | 显示"已锁存"，提供**显式重新使能**（`0x20 enable=1` 或 `0x21`）；**不要**用"继续"这类含糊按钮 |
| **低压锁存** | 电压 < 11.1 V 持续 5 拍 | 停车，**≥ 11.6 V 才自动解除**（迟滞） | 显示电压 + "低压保护中" |
| **倾角保护** | `|倾角 − Zhongzhi| > 40°` | 关电机（**手把车倾过去也会触发**） | 显示"倾角超限"（现场常见，不是故障） |
| **急停 `0x2F`** | 上位机发出 | 停车锁存，**只能用 `0x21` 解除**（`0x20` 解不开） | 急停按钮 + 明确的解除入口 |
| **`Flag_Stop`** | 未使能 / 按键停车 | 轮子不转 | 显示"已停车"；本机按键停车**不会被厂商"放下即启动"再次打开** |

## 5. C 侧需要同步的 5 项（清单）

1. **`frame.h`**：`kMotion` 长度 = **9**（不是 11）；新增 **`kDiag = 0x15`**、**`kInternals/kLoop = 0x16`**；
   补事件码 **`0x08` 失联 / `0x09` 解除 / `0x0A` 急停**（C 侧现已完成 ✅）。
2. **参数界面允许负值**（§3.1）—— 这条**务必确认**，本机正确值就是负的。
3. **显示固件版本字节**（§1）—— 排查"版本不符"类问题的唯一可靠手段。
4. **判读 `0x16` 的三个组合**（§2.1）做成提示 —— 尤其 `Turn=0 但 moto1≠moto2`。
5. **保活只用 `0x1F`**（§3.4）。

## 7. 复现验收（B 侧给 C 侧的现场判据）

| 判据 | 期望 |
|---|---|
| 手推前进，`0x16` 的 `encLeft/encRight` | **同号** |
| 使能后，倾角 | 收敛在 `Zhongzhi ± 1°` |
| `Turn = 0` 时 | `moto1 == moto2` |
| `ccr` 与 `moto` | `ccr ≈ 1.17 × |moto|`；`|moto|` 大而 `ccr = 0` ⇒ 保护态未执行 |
| 不使能（`Flag_Stop = 1`） | 轮子**不转**（停车保护有效） |
| 拔掉串口 500 ms | 安全停车并锁存；界面能显示并解除 |
