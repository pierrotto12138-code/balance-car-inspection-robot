| 39 | ★ **温湿度补偿用"除法"（`ratio_corr = ratio / factor`），不用 MQUnifiedsensor 的"叠加"，且默认关闭** | 两套开源用法用的是**同一个公式**：`factor = 0.00035t² − 0.02718t + 1.39538 − (h−33)·0.0018`，在参考点（≈19.4 ℃/33 %RH）≈ **1.0**。按"叠加"用等于凭空给 ratio 加 1.0（MQ-135 清洁空气才 3.6 → +28%），物理上讲不通；按"除法"用则参考条件不修正、偏离才修正。该系数来源本身存疑（GeorgK 源码自带 TODO），故**默认关闭**，由 0x23 的"补偿使能"控制，开启前必须实测复核并在报告注明 |
| 40 | ★ **ppm 只作估计值，且 `ppm×10` 上报前必须饱和钳位到 uint16 上限**；系数默认 MQ-2 = LPG（a=574.25, b=−2.222）、MQ-135 = NH4（a=102.2, b=−2.473） | ① 决策 18 已定"主链路用 Rs/R0，ppm 作展示"；② `ppm = a·ratio^b` 是幂律，ratio 很小时 ppm 可达千万级，**不钳位会回绕成小数字 —— 恰好把危险工况报成"浓度很低"**（已单测：1e6 → 65535）；③ 系数取自 MQUnifiedsensor 的 datasheet 曲线拟合，换目标气体只改这两个常数（MQ-135 若看 CO2 则 a=110.47, b=−2.862） |
| 41 | ★ **安全停车策略**：① 只在**曾收到过下行帧**之后才启用"500 ms 失联"判定（否则上电即停车）；② 安全停车**锁存**，链路恢复**不自动起步**，必须由 0x21 任务或 0x20 使能显式解除；③ 急停（0x2F）与硬件故障（低电压/倾角）走**同一条**停车通道，且急停**不能**被 0x20 解除（只有重下任务）；④ DHT 读不到**不阻塞任务**，只置"传感器失效"标志并自动停用温湿度补偿 | 仓库场景里"信号一抖车就自己冲出去"不可接受；一条停车通道比多条更好验证；单传感器故障不该让整个巡检任务瘫痪。已在 `firmware/tests/patrol_test.c` 里逐条脚本化验证（含"每 400 ms 有下行帧则永不误判"）|
| 42 | ★ **混合式架构的运行时策略**：① **两个中断（EXTI15_10 优先级 1、USART2 优先级 0）都不调用任何 FreeRTOS API**（含 `...FromISR`）——它们优先级高于 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY(5)`，中断里只做"塞字节进环形缓冲"；② 任务与中断之间只有两条通道：**SPSC 环形缓冲**（串口）与**短临界区读全局量**（仅用于上报/显示）；③ `delay_us/xms` 改 **DWT CYCCNT**（把 SysTick 让给内核），`delay_ms` 在调度器运行时用 `vTaskDelay`；④ `NVIC_PriorityGroup_2 → Group_4`；⑤ 串口发送（协议帧 + `printf`）用**互斥量**；⑥ **不需要 I2C 互斥量**——实板核实 OLED 是软件 SPI（PC0/13/14/15）、MPU6050 是软件 I2C（PB10/11），**不共总线**（`architecture.md` §3.3 的旧结论已改写） | 控制节拍是平衡车的命脉：它是**唯一不允许被调度器延迟**的东西；把 ISR 优先级保持原样 + 禁止 ISR 调 RTOS API，就能做到"加了 RTOS 但控制时序一字不改"。ISR 是否违规由 `tools/fw_prep/check_isr_safety.py` **静态核验**（编译器不会报，上板才炸）|
| 43 | ★ **ADC 拆通道**：`ADC1 → PB1`（电池，控制中断专用，保持厂商原样）；`ADC2 → PA5/PA6`（MQ-2 / MQ-135，GasTask 专用） | 厂商的 `Get_battery_volt()` 在控制中断里每次重设 ADC1 通道并软件触发；若任务也用 ADC1，两者会互相打断（中断改通道 → 任务读到别的通道；"等 EOC"标志被对方吃掉）。**任务侧临界区挡不住高优先级中断**，所以只能物理分开。PA5/PA6 同时挂在 `ADC12_IN5/IN6`，硬件上本来就能这么分 |
| 44 | ★ **转向环增益全局化**：`turn()` 里的局部常量 `Kp=52`、`Kd=0.5`（仅前后运动时取）改为全局 `Turn_Kp=52`、`Turn_Kd=0.5` 并定义在 `main.c`，供协议 0x24 在线调参 | 协议 §4.2 把 0x06/0x07 定义为 `Turn_Kp/Turn_Kd`，但厂商基线里它们是**局部常量**、根本无法调。改为全局且**默认值与原常量逐位相同** → 未调参时控制行为与基线完全一致（这一点必须在到货实测时确认，见开工准备 §14.6）|
| 45 | ★ **USART1 = 有线调试链路**（115200 8N1，与蓝牙**同协议、对等**）：收到帧就处理、回复**原路返回**；**周期上报与事件告警两条链路都发**；USART1 的 RX 中断在 RTOS 模式下启用，同样**只把字节推进环形缓冲**（不调 RTOS API） | 实验室调试与 PID 整定需要一条**不受蓝牙配对/干扰影响**的稳定链路；两条链路共用一套协议，避免出现"第二套协议"的维护负担。裸机模式下 USART1 仍留给厂商 DataScope（只发不收，中断不启用）|
| 46 | ★ **调参接口与持久化**：`0x24` 增加 4 个扩展参数 ID —— `0xFF` 全量回读（回 7 条）、`0x00` 存 Flash、`0xFE` 重新载入、`0xFD` 调参观测模式（开启后**有线链路 100 Hz** 上报 0x10/0x11）；参数以 **float 位型** 存于扇区 6（`0x08040000`），带 magic + 个数 + **数值合理性校验**，写入后**当场回读校验**；打包逻辑独立成 `param_pack.c` 并**原生单测 24 条** | ① **帧格式不变**（仍 N=6），只是"参数 ID"取值扩展 → 对 C 兼容、风险最低；② 100 Hz 观测是把 PID 调好的前提（20 Hz 看不出超调与振荡）；③ "存了却读不回来"极难查，所以把打包/校验拆出来离线验证；④ 不复用厂商 `0x08020000` 的存储区，避免互相擦除 |

## 三、传感器与硬件接入

| # | 决策 | 说明 |
|---|---|---|
| 13 | **气体传感器 = MQ-2 + MQ-135**（双通道交叉验证） | 模拟输出 AO 接 ADC |
| 14 | **每路 MQ 必须加分压**（推荐 10kΩ/15kΩ） | MQ 在 5V 下 AO 可达 5V，而 STM32 ADC 上限 3.3V，**直连会击穿引脚** |
| 15 | **MQ 加热丝需 5V 独立供电 + 去耦** | 约 150mA/路；就近加 100µF + 0.1µF |
| 16 | **MQ 需通电老化 24–48h** | 已在通电老化中 |
| 17 | **ppm 换算参考 `MQUnifiedsensor`**：`ppm = a·(Rs/R0)^b` | 参数已逐行核实，见 `docs/research/MQ气体传感器开源实现.md` |
| 18 | ★ **主链路用 Rs/R0 相对量做交叉验证，ppm 作"估计值"展示** | 绝对浓度精度不可靠；泄漏定位需要的是**灵敏度 + 相对比较** |
| 25 | ★ **红外避障 L 从 PA4 改接 PB12** | **PA4 不是 5V 容忍脚**（`TC`），而红外模块 OUT 在 5V 供电下输出约 5V → **直连会击穿**。`PB12` 是 `FT`（5V 容忍）|
| 26 | ★ **蜂鸣器 = 有源模块 + `PC5` 直连**（新增 `J18`） | 实测是**有源**（自带振荡）、**低电平触发**、**5V**。`PC5` 是 5V 容忍，可直连模块 I/O；**不用 `Q1/R7/R8/BZ1`**。固件极性：**低电平响** |
| 27 | ★ **8 个模块座全部"按模块丝印"重排引脚顺序** | 复制粘贴会带过来原板旧序；逐座核对模块丝印后发现有 8 处会导致 **5V 直灌 3.3V 脚 / 反极 / TRIG·ECHO 反接**。直插不改线 = 会烧 |
| 28 | ★ **新增阻容统一 0805**（原板 0603） | 手焊友好。实测引脚几何：0603 电阻垂直 30 间距 / 0805 水平 40 —— **替换器件会弄断导线**，所以换封装只能靠"属性面板改封装"，不能"替换器件" |
| 29 | ★ **电机功率走 `+12V`，不走 `+5V`** | 实测 `U1`(TB6612) 的 `VM1/VM2/VM3` 全接 `+12V`，只有 `VCC/STBY` 接 `+5V`。**所以 `L1` 那个"33µH 5A"是过设计**，5V 那路只有 MCU+传感器约 0.5A |
| 30 | ★ **红外避障两个座（`J11`/`J14`）保留焊盘、不焊排针（DNP）** | A1 只买了 1 个红外模块，且判断**超声波避障已足够**。但：① **任务书里"HC-SR04 **与红外模块**负责避障与循迹"是明确写了的**（有合规风险）；② **删掉容易、加回来贵** —— PCB 阶段删了以后要用，就得改原理图 + 重画 PCB + 重新打板。故**保留两个 3 脚座与走线，不装排针**。**零成本、可逆、任务书也对得上**。`PB12`/`PC1` 两个 IO 因此空闲 |
| 31 | ★ **`J15`（5V/GND 取电排）保留，可先不焊** | 它是给外挂模块就近取电用的便利排，不是信号座。焊上更方便调试，不焊也不影响功能 |

| 1 | API 创建的元件字段不完整 | 老元件含 `DeviceName`/`FootprintName`，API 创建的新电阻**缺这两项** |
| 2 | `pcb_Document.importChanges()` 在本工程恒返回 false | 用未改动的原工程测试同样 false |
| 3 | **PCB 自动布线 DRC 难以收敛** | 板子双面高密度（Top 818 / Bottom 709 个障碍），新元件无论放哪都压到既有走线；最终仍有 96 条间距错误 |

> **所以"AI 自动画 PCB"确实不行** —— 改板走**手工画 PCB**（见 `焊接调试手册.md`）。

#### ★ 但 2026-09-30 的实测把"原理图也改不动"这条推翻了

**做法**：仍然用同一套 EDA API，**只改原理图**（放件、接线、填料号、改封装）。

| 成果 | 数据 |
|---|---|
| 用 API **放入元件** | 12 只（`R10~R14`、`C14~C19`）+ 多个候选替换件 |
| 用 API **连线** | 约 40 条（8 个模块座的座序重排、分压/上拉/去耦、`J18`、`SW2`/`J17`）|
| 用 API **写料号** | `U1/U2/U3` + `D1` 等 |
| 用 API **改位号** | `C21→C2`、`C24→C13`、`L2→L1`、`U5→U2`、`U6→U3` |
| 核验 | 逐脚网络 + 全局防短路 + 文件层解析 **三路径复核通过**；**DRC 致命错误 0** |

**关键突破**：`create(<从 lib_Device.search() 拿到的完整器件对象>, x, y)` **能成功且封装齐全**；
传 `{libraryUuid, uuid}` 引用会卡死 30 秒（原因见《原理图完善计划》§6.5 的四个坑）。

#### ★★ 2026-10-07 实测（第二次修订）：**PCB 布局仍然做不了** —— 能力边界最终版

**试了什么**：在"改"板 PCB2 上，用 API 自动摆放开关电源区 10 个件（`U2/L1/D1/C1~C6/U3`）。

| 尝试 | 结果 |
|---|---|
| **算面积、找空位** | ✅ **这部分有用**：极大矩形算法能算出板内哪块是空的。实测这 10 个件**纯器件面积 = 467 mm²**（≈21.6×21.6 mm 的方块），加布线余量要 **25~30 mm 见方** |
| **螺旋自动寻位** | ❌ **失败**：把元件推散 —— `C4↔C2` 仍有 23 mm（目标 ≤6 mm），`C1↔U2` 15 mm |
| **定向精修** | ❌ **失败**：撞到 `J18` 和板框，且**每改一步都要 A1 善后** |

**结论（A1 的判断，记录采纳）**：
> **AI 目前做不了 PCB 布局。** 布局是"全局优化 + 经验 + 反复权衡"的活，
> 而 API 只能"一个件一个件挪"，看不到整体，越改越乱。
> **要试也只能在复制出来的沙盒板上试，别动正板。**

**因此确立最终分工**：

| 谁 | 做什么 |
|---|---|
| **A1（人）** | **PCB 摆放与布线**（全局判断，AI 替代不了）|
| **AI** | **核查类**（这部分做得好）：DRC 运行与判读、网络表一致性、**间距/线宽实测**、丝印检查、BOM 料号核对、原理图改动与核验 |

**另一个重要发现**：A1 原先的 PCB 布局是**照抄"原"板 PCB1** 的 —— 这个做法本身是对的，
**但"替换器件"会把封装原点带偏**（`CP_Elec_8x5.4` → `CAP-SMD_BD8.0` 的原点/焊盘不同），
于是抄来的相对位置就失真了（`C4↔C2` 从紧邻变成 38 mm）。
**所以换过封装的元件，位置要重新对一遍。**

#### ★★ 2026-10-07 第三次修订：**"照抄原板布局"是完全正确的 —— 我批错了对象**

A1 反问："既然原板用那个布局，为什么说误差不可接受？"
**实测数据支持 A1，我之前的批评搞错了对象**：

| 配对 | **原板 PCB1（实测）** | 改板 PCB2（走样后） |
|---|---|---|
| `C4↔C2` | **6.2 mm** ✅ 紧贴 | 25.7 mm |
| `C5↔U3` | **5.8 mm** ✅ | 44.9 mm |
| `C3↔U2` | **7.9 mm** ✅ | 38.9 mm |
| `C2↔L1` | **10.2 mm** ✅ | 44.2 mm |
| `C1↔U2` | **14.4 mm** ✅ | 25.5 mm |
| `D1↔U2` | **13.9 mm** ✅ | 46.5 mm |
| `L1↔U2` | 20.5 mm 🟡 | 14.6 mm |

**结论：原板的电源布局本来就是紧的、正确的。**
我之前看到的"38 mm / 44 mm"**不是原板的布局**，而是**改板照抄时走样的结果** ——
**批评对象搞错了，特此更正。**

**为什么会走样 —— 找到了根因**：两块板**板框尺寸完全一样（100 × 60 mm）**，但 **坐标系差了 2079 mil**：

| | 板框 y 范围 | 安装孔 y |
|---|---|---|
| 原板 PCB1 | −43.35 → 2318.85 | (0,0) (0,**+2079**) |
| 改板 PCB2 | **−2122.35 → 43** | (0,0) (0,**−2079**) |

**换算公式：`y_改 = y_原 − 2079`，x 不变。**
照抄原板坐标时**必须做这个换算**，否则整块板会偏 52.8 mm。

**修正后的指导**：
- ✅ **A1 照抄原板 PCB1 的布局是正确做法**（那是量产验证过的设计）
- ✅ **只有"开关回路"那一圈（`U2.OUT↔D1↔L1↔C2`）真正要紧**，而原板已经做到了
- ⚠️ 换过封装的元件（`C1/C2/C6/C10/C13/L1/SW2/J17/U1/U2/U3/D1`）抄坐标后要微调几 mm

**结论修正**：
- **原理图**：**AI 自动化完全可行** ✅（"人放件、机器接线"可以进一步变成"机器全包"）
- **PCB 自动布线**：**仍不可行** ❌，PCB 靠手工

**处置**：`参考01_copy` 的"改"板原理图已由 API 完成并落盘；
PCB 由 A1 手工绘制（`参考01_copy` 的原始干净状态仍保留在 `projects\参考01\`）。
