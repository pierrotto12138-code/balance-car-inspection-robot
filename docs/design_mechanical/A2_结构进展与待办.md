## 5. SolidWorks 会话怎么开（2026-10-17 打通）

免装 CAD 的离线链路（本仓库 `tools/`）仍然是主力；**需要"真 CAD 的权威判断"时**才开它：

```powershell
# 安装目录自带的 CLI；桌面版是单实例，不能靠再开一次 exe 换 profile
& "…\DeepSeekHarness\resources\runtime\cli\bin\dsh.cmd" --profile solidworks --port 19388 --no-open
```

- 得到一行带 token 的 `http://127.0.0.1:19388/…`，浏览器打开即**独立会话**（9 个 `mcp__solidworks__*` 工具）。
- 两个坑（都实测过，已在集成记录里写清）：① MCP 的解释器必须是集成包自带的 venv，**DSH 运行时自带的 python 没有 `mcp` 包**，表现为"界面起来了但一个工具都没有"；② 桌面窗口与它共用同一个 asar，但**端口必须错开**。
- 职责边界：**改模型/出图**在 SW 会话里做；**文书、批量整理、STEP/STL 处理**留普通会话。

> 判据纪律（沿用全仓库口径）：`工具调用成功 ≠ 尺寸/拓扑已验证`；没做过的检查写"未做"。

## 7. 2026-10-17 实测：两处"名不副实"，已修

| 缺陷 | 证据 | 修法 |
|---|---|---|
| **"装配"STEP 没有装配树** | `A2-10_整车_装配_轻量.step` 里 `NEXT_ASSEMBLY_USAGE_OCCURRENCE` = **0**（14 个 PRODUCT 各自独立）；根因是 `AddShape(shape, False)` 只加"自由件" | 新增 [`tools/step_assembly.py`](../../tools/step_assembly.py)：复合体 → `makeAssembly=True` → 逐组件 `GetReferredShape` 命名。修后 **PRODUCT 25 / NAUO 24**（14 个命名件，电机各 5 个子实体）|
| **`A2-00_外壳装配.step` 其实是 1 个实体** | 旧版 `fuse(下壳, 上壳)`，文件里 `MANIFOLD_SOLID_BREP` = 1（"2 实体"是错的）| 改写成真装配：**PRODUCT 3 / NAUO 2 / 实体 2**（`shell_assembly` → `lower_shell` + `upper_shell`）|

**顺带定下的判据**：`STEPControl_Writer.Write()` 返回 `RetDone` 只说明**文件写完了**，
不说明结构对 ⇒ 一律再按文本数 `PRODUCT(` / `NAUO` / `MANIFOLD_SOLID_BREP`，
断言"PRODUCT = 件数+1、NAUO = 件数"（`step_assembly.describe()`）。

**待人工确认的一条**：本机 SolidWorks 2026 **打不开任何 STEP**（`errors=2097152`；AP203/AP214、
`.step`/`.stp`、中文/纯 ASCII 路径全都一样；同一套通道下 **STL 正常**）⇒ 属导入器问题，
不是我们的文件。GUI 里手开一次即可定性；在此之前，"权威 CAD 判断"仍以离线几何内核为准。
